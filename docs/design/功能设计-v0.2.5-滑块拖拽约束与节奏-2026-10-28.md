# 功能设计 v0.2.5 —— 滑块拖拽约束与节奏（拖拽可用化）

日期：2026-10-28　版本：v0.2.5（commit 3545780）
前序：v0.2.4（人类化轨迹）→ 本版把「形态像人」补成「时序也像人」，并修掉滑块场景的致命伤。

## 0. 缘起与用户需求

v0.2.4 的拖拽在 awsearch 实弹联调中被测出**纵向漂移**：水平拖 520px 纵向漂 50.5px——
滑块/进度条这类被约束在轨道上的控件直接脱轨。用户两条定版需求：

1. 「修复一下，顺便把前面发现的 bug 也修复了，然后复审一下修改的地方」——
   复审采用**对抗模式**（独立审查方，非自审），实锤 3 致命 / 6 严重 / 6 建议，全闭。
2. 「短距离拖拽比人快一倍，这个要**可以调参数**的，**验证码类慢点**」——节奏必须可调。

## 1. 拖拽两档轨迹（致命修复 F-1）

**根因**：v0.2.4 的 `drag_events` 复用了 `human_move_events`（为"鼠标自由移动"设计），
其贝塞尔控制点弓形偏移 `bow = dist × 10%~25%` **按距离比例放大**。自由移动走弧线是
"像人"的特征；但**拖动控件时物体被约束在轨道上，弧线就是错的**。

实测漂移（修复前）：100px→8.8px，200px→21.5px，300px→30.0px，520px→**50.5px**。

**修法**：轨迹核心抽成 `_trajectory(..., constrained)`，两档契约：

- `constrained=True`（**拖拽缺省**）：主轴线性插值（缓动照旧），垂直方向只抽
  **一个标量** `perp ∈ [-max_perp, +max_perp]` 乘单位垂向量——偏移严格垂直于主轴、
  幅值 ≤ max_perp（缺省 2.5px），**与距离无关**。主轴方向另有 ±0.4×max_perp 的
  沿轴微抖（不影响落点精度）。
- `constrained=False`：自由拖拽（画图/框选），保留贝塞尔弧线。

> **实现陷阱（审查 S2 实锤）**：第一版对 x/y 各抽一次随机偏移——两次独立抽样让
> 偏移向量**不再垂直于主轴**，幅值上界变成 √2×max_perp（300 seed 扫描实测最大
> 2.956 > 2.5）。修法就是"抽一个标量再乘单位向量"，一行代码的事，但不知道这个
> 坑就会写出"看起来对"的错误。

末端**过冲回退**：拖过头 1~3px 再拉回（人类调整动作），由档位给幅度。

## 2. 节奏三档（用户需求，致命修复 F-2 的"可见"半边）

```python
PACES = {
  "fast":    base=120, per=0.45, clamp 150~600ms,  over=0,        settle 15~30ms,
  "normal":  base=260, per=1.10, clamp 320~1400ms, over=1~3px,    settle 30~70ms,
  "captcha": base=700, per=2.40, clamp 900~2600ms, over=3~6px,    settle 60~130ms,
}
total_ms = clamp(base + dist×per, lo, hi) × rnd.uniform(0.88, 1.1)
```

- **captcha 档**（过滑块验证码用）：总时长 900~2600ms + 末端明显过冲回退——
  过顺滑反而像脚本；真人拖滑块普遍 400~1200ms，captcha 档刻意再慢一档。
- 显式 `total_ms` **优先**于档位；`total_ms=0` / `timing=false` = **真全速**——
  连按下后 40~90ms 的发力停顿、末端 settle 一起归零（审查 S3 实锤：否则
  "不等"的承诺是假的）。
- 每步延时按**缓动进度差分**（Δte）分配，不是按距离——速度曲线是设计出来的
  （慢-快-慢），距离大的那步本来就该"走得久一点"；按距离分配等于把速度拉成匀速。

## 3. Session 化派发（致命修复 F-2 的"根因"半边）

v0.2.4 的 `dispatch()` 对每个事件调一次 `call()`，而 `call()` 是**一命令一连接**
（握手→发→收→关）。实测 17ms/事件——全是重连开销。后果：缓动速度曲线只体现在
**空间采样密度**上，时间上每点间隔完全均匀——"绝对均匀"比真人更可疑。

**修法**：新增 `Session` 类——一次握手，id 递增逐条收发（`_recv_frame` 的 buf 线穿
保持）；`dispatch()` 用 Session + 逐事件 `time.sleep(_delay_ms/1000)`。

**诚实化**：等待被 3s 上限夹断时收据亮 `clipped_ms`，不静默；`stats` 参数回带
`planned_ms / slept_ms / clipped_ms`。

**收据承诺**：`dispatched: N` 只说明事件发出，**不说明生效**——drag/click/type 加可选
`verify` 参数（一段 JS，操作后求值，结果进收据）。

## 4. 新工具：eval / view（审查严重项 S3）

13 个工具里没有 JS 求值和视口信息，导致"算坐标靠外部工具""操作完无法确认生效"。

- **`ashot_cdp_eval(js)`**：Runtime.evaluate，函数体自动包 IIFE。只发 evaluate、
  **绝不发 Runtime.enable**（字节系检测点，一发即杀实例——awsearch 实弹红线）。
- **`ashot_cdp_view()`**：`Page.getLayoutMetrics` 的 vw/vh（CSS 像素）+ 整页 content
  尺寸 + devicePixelRatio。
- **`ashot_cdp_shot` 收据升级**：补 `w/h`（PNG 真实像素）、`vw/vh/dpr`、**`to_css`**
  （截图像素 × to_css = 点击用的 CSS 坐标）、失败亮 `layout_error` 不吞主收据。

> **to_css 的实现陷阱（审查 F2 实锤）**：第一版写 `min(vw/w, vh/h)`——全页截图时
> vh 是视口高而图高是整页（content_h×dpr），相除小一个数量级（实测 0.102 vs 正确
> 0.5）。屏幕像素→CSS 像素是**各向同性缩放**，`1/dpr` 一个系数就够。

> **eval 的实弹陷阱（本版实测）**：Runtime.evaluate 的 expression **不认裸 `return`**——
> `return 6*7` 静默 undefined（无报错！），多语句函数体整体失效。修：含
> return/分号/换行自动包 `(function(){...})()`，与 awsearch eval_js 同款约定。

## 5. 多实例安全边界（审查建议项 S6）

`discover()` 命中多个调试端口时**不再静默取 [0]**——静默取第一个会把鼠标事件打到
完全不相干的浏览器实例上（实测曾把另一个工具 ALrec 的 9225 当成目标）。修法：

- **输入类动作**（click/drag/key/type/wheel/eval/view/shot）：多实例时**报错**，
  错误信息列出各实例首个页签的 title/url，让人一眼挑出目标；
- **只读的 `cdp-tabs`**：允许一次列多实例（返回 `groups:[{port, tabs}]` 分组结果）。

## 6. 诚实化与兼容

- `dispatch` 不再**就地 pop** 调用方的事件 dict（`_delay_ms`/`unresolved`）——同一
  seq 重试时不再丢节奏、丢亮牌；
- click 靠近轨迹现在有 120~320ms 的节奏耗时——批处理可用 `--no-timing` /
  `timing=false` 关闭；`--teleport` 照旧瞬移；
- drag 步数下限 10→18（旧值短距离太稀疏：100px 只 13 事件/185ms，比人快一倍）；
- `constrained` 缺省 True **改变了 drag 既有行为**——需要旧弧线的调用方显式传
  `constrained=False`（CLI `--free`）。

## 7. 对 v0.2.0 文档 §4.2.3 的覆盖

v0.2.0 设计文档记录的「**比人快：无真实延时**」「时序拟真属于未来 batch」自本版起
**已被覆盖**：时序拟真（事件级节奏）已在 v0.2.5 落地。「轨迹随机≠不可检测」的诚实
边界仍然成立——形态+时序都像人，不等于不可检测（高级风控仍可统计辨识），不夸大。

## 10. 遗留与边界

- **rotate / click 型验证码**：仍不支持（awsearch captcha.py 明确报
  `unsupported_kind` 转人工）——本版只保证 slide 型的"拖"这一半可用；
  缺口识别（找 x 偏移）在 awsearch captcha.py（矩形四边梯度取 min，合成图 9/10）。
- **首次实弹线上验证未做**：合成图/画布 ≠ 抖音真滑块（真图有 canvas 暗化、
  行为分、频率权重）。首个线上机会应记录通过率，别拿合成数据打包票。
- 速度曲线"像人"没有黄金标准：captcha 档参数是按"真人拖滑块 400~1200ms 再
  慢一档"定的，可按线上通过率回调 `PACES`。
