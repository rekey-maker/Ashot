## 2. 五组设计决策

### 2.1 文本：原生换行 + 实测告警（Q15）

- **不自己估字宽**。text op 新增 `w`（布局矩形宽，像素）→
  `DrawString(String, Font, Brush, RectangleF)`，换行由 GDI+ 按**真实
  字体度量**完成（业界正解；Python 侧按 CJK=1×size/ASCII=0.55×size 估算
  的方案作废）。
- **告警优于裁切**：`_gdi_render.ps1` 对每个 text/dot 调 `MeasureString`，
  末行输出 `{"ok":true,"boxes":[{i,x,y,w,h}]}`；Python 用 `i`（op 下标）
  对齐，和画布尺寸比对，写 `bounds_warn: ["op[0] text 超出画布：右 135px"]`。
  不自动裁切（裁切会悄悄丢内容），也不自动扩画布。
- 像素降级路同步认 `w`（点阵贪心折行），语义对齐但精度天然不同——
  收据已用 `backend` 区分。

### 2.2 预览：缺省开、预算减半（Q16）

- `ashot_shot` / `ashot_annotate` / `ashot_cdp_shot` 的 `preview` 缺省
  改为 `true`（用户实感：截完还要再 read_image 一跳）。
- 预算 500KB → **200KB**（缺省开之后每次调用都进上下文，200KB 对
  "确认截对了"足够）；梯次降档逻辑不变。
- **高度也限**（v0.2.6 实弹修正）：只按宽度缩，49446px 长页的"缩图"
  仍有 2.8MB；现在等比缩到高 ≤4000px（宽度会被压窄，但上下文安全），
  info 带 height。
- `preview=false` 仍是单字符串收据（兼容 + 省上下文）。
- 边界不变：ImageContent 在 ZCode 上只喂模型、不渲染用户；用户看图
  仍走 `ashot_show` + `::visualize`。

### 2.3 窗口：可见帧界（Q17）

- `--win` 优先 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS=9)`，
  失败回退 `GetWindowRect`，并标 `box_source`（`dwm`/`rect`）。
- 本机实测：GetWindowRect 446×331 vs DWM 424×320（左/右/下各多 11px
  不可见 resize 边与阴影留白）。
- `hwnd=0`（锁屏/服务态/桌面切换）抛可读错误，不再拿 0 去
  `GetWindowRect`（行为未定义）。

### 2.4 发现：并发 + 亮牌 + 身份（Q04/Q20）

- **进程枚举不再吞错**：检查返回码与 stderr，失败进 `warnings`
  （Win11 上 `Get-CimInstance Win32_Process` 可能 Access denied——
  旧实现只看 stdout，静默退化为端口扫描）。
- **探活并发化**：8 端口并发 + 0.6s 超时，实测 14.3s → 0.94s。
- `discover` 返回 `details/confidence/warnings`；单实例也**不再静默**：
  `target`（端口/进程名/页签 title+url）进收据。
- **多实例纪律扩到 cdp-shot**（原只有输入类拒绝）：截图拍到错浏览器
  也是错，不许静默取 `[0]`。

### 2.5 可观测性：ver / degrade_reason / coord_space / value_type

- 收据 `ver`：由 `_serve` 单一出口盖章（15 个工具全覆盖）——文件版本
  号对了但进程是旧的，一眼识破。
- `degrade_reason` + `backend_fallback`：矢量路失败原因（PS 返回码/
  stderr/超时/异常）落收据。
- `gdi_error`：主路失败原因在兜底成功时也保留；双腿全废时两条一起抛。
- `coord_space` + `scroll_y`：全页截图是**文档坐标**，hint 明说要点
  首屏以下需减 `scrollY`（旧的 `min()` 数值 bug v0.2.5 已修，残的是
  语义误导）。**判据先看图像实际覆盖的 CSS 高（`sz[1]/dpr`），再退回
`content_h`**：
  `dpr` 求值失败是真实路径（evaluate 单独 try），此时图高会按 dpr 放大，
  用图高或 `dpr or 1` 推断会把视口截图标成文档坐标、`to_css` 同时错一倍
  （独立审查 S1）。**二轮实锤（S2）是单位错**：`getLayoutMetrics` 的
  `contentSize`/`layoutViewport` 是已废弃字段、**可能是设备像素**
  （实测 Edg156：contentSize=2544×1632 vs cssContentSize=1272×816，
  dpr=2）——旧实现当 CSS 用，整页高被高估 dpr 倍。改取
  `cssContentSize`/`cssLayoutViewport`（旧协议无 css* 时按 dpr 折算并标
  `content_source`）；坐标空间判据优先看**图像实际覆盖的 CSS 高**
  （`sz[1]/dpr`），dpr 缺失才退回 content_h 并标 `to_css_estimated`。
  页高超过截图上限 / 只截到视口时，收据亮 `fullpage_truncated` 并写明
  "只截到 N CSS"——不假装整页。dpr 与 content_h 都拿不到则
  `coord_space: "unknown"`。
- `value_type`：`cdp-eval` 区分 `undefined`/`null`/不可序列化 object。

### 2.6 超长页：滚动拼接（v0.2.6 追加）

- **上限是环境相关的**：同一份代码，Playwright 拉起的 Edge 一次能拍
  60000px（0.46s），另一实例 17000px 就报 "Unable to capture
  screenshot"——所以不做固定阈值预判，**先试单张、失败才拼**。
- **做法**：单张失败 → 按视口逐屏滚动拍（JS
  `scrollingElement.scrollTop`，不生效退鼠标滚轮），每屏按**实际
  scrollY × dpr** 贴到 RGBA 画布，`output.rgba_to_png` 出图，拍完
  `scrollTo(原位置)` 复原。默认自动，`stitch=false` / `--no-stitch` 关闭。
- **收据**：`stitched:true`、`shots:N`、`coord_space=document`、
  `fullpage_truncated`（画布像素上限 40MP 触顶时）。
- **诚实边界**：固定定位元素（吸顶栏）逐屏重复；内层滚动容器若
  `scrollTop` 不动会提前停并如实标注；拼接分辨率受 dpr 与内存限制。

## 3. 契约变更（可能影响既有调用方）

| 变更 | 影响 | 逃生口 |
|---|---|---|
| 三处 `preview` 缺省 true | 每次多一次缩图子进程（约 0.3s）+ ImageContent | `preview=false` |
| 多实例时 `cdp-shot` 报错 | 旧行为静默取 `[0]` | 显式 `--port` |
| 单实例收据多 `target` | 字段新增，不破坏解析 | — |
| 收据多 `ver` | 同上 | — |
| `--win` 尺寸变小（去掉阴影边） | 配图不用再自裁 | 需要旧行为就 `--area` |
| CLI `allow_abbrev=False` | `--ops` 这类缩写不再被猜 | 用完整参数名 |

## 4. 反指纹（Q12）

点击的接近轨迹起点从恒定 `(0,0)` 改为目标周围 140~420px 随机方位
（seed 可复现），并开放 `from_x/from_y` / `--from-x/--from-y` 显式指定。
诚实边界不变：**形态+时序像人 ≠ 不可检测**，高级风控仍可从速度分布
统计辨识。
