# 功能设计 v0.6.0 —— MCP 精确定位（结构化快照 + 元素标注）

> 日期：2026-10-29　版本：v0.6.0　基线：v0.5.1（commit `0b34495`）
> 缘起：用户问「有没有办法让 MCP 也像 CLI 一样画图定位精准」。
> 结论：**MCP 与 CLI 共用同一套核心，精度差不在画图，而在"坐标从哪来"**——
> 模型看的是缩小后的预览图，靠目测得坐标必然偏。解法不是更强的视觉模型，
> 而是**用结构化元素（ref/selector）代替像素猜测**。

## 1. 精度差在哪（先定位问题）

| 来源 | CLI | MCP |
|---|---|---|
| 坐标来源 | agent 可跑 `element` 拿 CSS 矩形、算好再喂 `annotate` | 模型往往直接看 `preview`（≤200KB、可能缩到 1200px）目测坐标 |
| 元素指代 | 选择器 / 坐标都行 | 只有绝对像素；选择器得自己先调 `element` 抄数字 |
| 坐标换算 | 人/脚本乘 dpr | 预览坐标 → 源图坐标**没有系数**，只能猜 |

所以三件事：**元素级定位、坐标换算元数据、结构化快照**。

## 2. 调研（2026-10-29，一手 README/源码）

| 项目 | 机制 | 对 Ashot 的取舍 |
|---|---|---|
| [Playwright MCP](https://github.com/microsoft/playwright-mcp)（[snapshots 文档](https://playwright.dev/mcp/snapshots)） | accessibility snapshot 给每个节点 `[ref=eN]`，点击/输入收 ref；文档明确「refs 比坐标准、截图只作视觉补充」；README 还承认 CLI+Skills 对编码 agent 更省 token | **采用**：DOM 快照 + ref → 元素定位。不引 Playwright，纯 CDP `Runtime.evaluate` |
| [OmniParser](https://github.com/microsoft/OmniParser)（微软，MIT） | 纯视觉：YOLO 检测可交互区域 + caption 模型描述；无需 DOM | **不采用**：要模型权重/推理依赖，破零依赖；仅作无 DOM 场景参考 |
| Set-of-Mark（[实测文](https://www.scrapeless.com/en/blog/set-of-mark-browser-agent)） | 在元素上叠加编号框，视觉模型按编号指代，显著降低 grounding 误差 | **后续**：桌面/Canvas 无 DOM 时用 `ashot_marks` 叠加编号 |
| [Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp) | 全量 DevTools + Puppeteer，a11y/DOM 都能取 | 说明"结构优先"是共识；Ashot 只取最小子集 |
| [browser-use](https://github.com/browser-use/browser-use) | DOM 索引 + 视觉混合 | 同方向；Ashot 保持零依赖、不自带 agent |

## 3. 方案（已实现）

### 3.1 `ashot_snapshot` / CLI `snapshot`

- 纯 `Runtime.evaluate` 遍历 DOM，输出：
  ```
  - body "提交"
    - button "提交" [ref=e1] [box=120,80,100,40]
    - input [ref=e2] [box=120,160,200,30]
  ```
- `refs` 映射：`e1 → {selector:"#btn", tag, text, rect}`；`count/url/title/dpr/scroll` 进收据。
- 只收"可交互/有文本叶/有 role"的节点，`max_nodes` 缺省 150（控 token）。
- **不碰 Accessibility 域、不抓图**；DOM 选择器用 id 优先 + `nth-of-type` 回退。

### 3.2 `annotate` 的 ops 支持 `selector` / `ref`

```json
[{"kind":"rect","selector":"#submit","width":4,"color":"#FF3B30","pad":2},
 {"kind":"text","ref":"e5","text":"点这里","size":24}]
```

- 矩形族（rect/ellipse/mosaic/blur/spotlight/smarterase）填 `x/y/w/h`；
  text 填左上角；箭头/直线**拒绝**（两端元素语义没定，不猜）。
- `CSS × dpr = 截图物理像素`；`pad` 外扩；`dpr` 可显式覆盖。
- CLI 加 `--port/--index/--ws`；MCP 同名参数；ref 用最近一次 `snapshot`
  的映射（跨进程/跨页失效，如实报错）。

### 3.3 预览坐标映射

`preview` 收据新增：

```json
"preview": {"width": 1200, "height": 800, "src": [2544, 1632],
            "to_source": 2.12, ...}
```

模型在预览图上读到的坐标 × `to_source` = 源图坐标。不保证模型会算，
但至少**有系数可算**，不再靠猜。

## 4. 边界（诚实）

- **视口 vs 整页**：`element`/snapshot 给的是视口 CSS；整页截图要加
  `scroll`（收据里有），本版不自动加。
- **非 DOM 场景**（桌面应用、Canvas、游戏）：snapshot 不可用，仍靠坐标；
  下一步做 `ashot_marks`（Set-of-Mark 编号叠加）或网格标尺。
- **ref 生命周期**：仅最近一次 snapshot；页面变化后请重拍。
- **iframe**：snapshot 只走主文档；iframe 内元素请用 `frame-element`。
- **不做**：视觉模型/OCR/OmniParser 集成（零依赖红线）。

## 5. 测试与证据

- 171 项全绿（+3：快照树/refs、selector/ref/pad、`to_source`）。
- 真机 Edge：
  - `snapshot` → `button "提交" [ref=e1] [box=120,80,100,40]`，refs 映射 `#btn`；
  - `annotate` 用 `{"kind":"rect","selector":"#btn"}` 画框，红色 bbox
    =(119,79)-(221,121)（线宽 3 骑在 120..220 边界上，中心正确）。

## 6. 后续（按性价比）

1. `ashot_marks`：快照框 + 编号叠加到截图上（SoM），服务视觉模型/桌面；
2. `cdp_click(ref/selector)`：点击也走元素，不再传坐标；
3. `snapshot` 支持 iframe（复用 frame-element 的 frameId 路由）；
4. 整页截图自动加 `scroll` 偏移。
