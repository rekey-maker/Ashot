# 功能设计 v0.4.1 —— 曲线 / 弧线 / 折线（三件矢量原语）

> 日期：2026-10-29　版本：v0.4.1　基线：v0.4.0（commit `13efee0`）
> 缘起：用户问「能画直线，那能不能画斜线？或者曲线、弧线？」——
> 斜线本来就支持（`line`/`arrow` 收任意两点）；曲线/弧线确实没有。
> 用户裁决：**加，而且要和箭头同一条原理（矢量图合成，不是像素硬边）**。

---

## 0. 一句话

给 Ashot 补三件**描边类**矢量原语：`curve`（三次贝塞尔）、`arc`（椭圆弧）、
`polyline`（折线）。实现方式与箭头完全一致：**几何在 Python 采样成点列 →
GDI+ 用抗锯齿 Pen 描边**；像素降级路复用同一套采样（只是硬边）。

## 1. 调研（一手文档，2026-10-29）

| 来源 | 结论 | 我们怎么用 |
|---|---|---|
| [Graphics.DrawBezier (Microsoft Learn)](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics.drawbezier?view=windowsdesktop-8.0) | 三次贝塞尔由 **4 个点**定义：起点、两个控制点、终点；"drawn from the first point to the fourth point" | `curve` 的参数就是这四个点（8 个数） |
| [Graphics.DrawArc (Microsoft Learn)](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics.drawarc?view=windowsdesktop-8.0) | 弧=椭圆的一部分，由**外接矩形**定义；`startAngle`/`sweepAngle` 单位是**度**，**从 x 轴顺时针**，终点 = start + sweep | `arc` 用 `x,y,w,h,start,sweep`；采样用参数方程 `(cx+a·cos t, cy+b·sin t)`，屏幕 y 向下时 t 增大同样是顺时针，与 GDI+ 一致 |
| 曲线细分惯例（de Casteljau / 固定弧长步进） | 采样密度应随曲线长度自适应，而非固定段数 | 按**控制多边形长度** / 4px 取点数，夹 16~128；弧按 ~2°/段，夹 8~180 |

**为什么仍走「采样成点列」而不是直接调 DrawBezier/DrawArc**：
1. GDI+ 内部本来就把曲线展平成折线再描边，两者像素结果等价；
2. 保持本项目的几何纪律——**几何全在 Python（可单测），渲染端只忠实画线**
   （设计文档 §7.6.4：PS 零形状数学）；
3. 渲染脚本、像素降级路、CLI/MCP 参数**都不用改**，风险最低；
4. 越界告警（`bounds_warn`）直接复用「按点列算 bbox」，不额外造轮子。

## 2. 契约

| kind | 参数 | 说明 |
|---|---|---|
| `curve` | `x0,y0,c1x,c1y,c2x,c2y,x1,y1` | 三次贝塞尔；也收 `points=[[x,y]×4]` 或 `coords="8 个数"` |
| `arc` | `x,y,w,h,start,sweep` | 外接矩形 + 起止角（**度**，顺时针）；`sweep` 负=逆时针，>360 夹到一圈；可用 `end` 代替 `sweep`（sweep=end−start） |
| `polyline` | `points=[[x,y],...]` | 或 `coords="x1,y1,x2,y2,..."`；连续重复点自动合并，<2 个不同点报错 |

- 三者都是 **stroke**（描边），吃 `color` / `width`，与 rect/line 同语义；
- 端帽/拐角 = RoundCap/RoundJoin（与箭头同一套，圆头不扎眼）；
- 越界：bbox 由采样点算（含半笔宽），照样进 `bounds_warn`；
- 非法几何一律抛错不静默：`sweep=0`、`w/h≤0`、点数不足、缺键。

## 3. 实现

新增 **`ashot/geometry.py`**（纯数学，无依赖）：

```
bezier_points(x0,y0,c1x,c1y,c2x,c2y,x1,y1)  # 控制多边形长度 → 步数 16~128
arc_points(x,y,w,h,start,sweep)             # |sweep|/2° → 步数 8~180，夹 360°
polyline_points(points)                     # 去重、校验 ≥2 点
parse_curve / parse_arc / parse_polyline    # 两路共用的 op 解析（三种写法）
```

复用点：`vector.compile_ops` 与 `annotate.annotate_png` 都调同一套
`geometry` ——**不重复实现**。这一条是刻意的：imgtool 的两套箭头几何
（8×width 硬编码 vs 3.5×width 短箭封顶）就是「抄两遍」的教训。

## 4. 测试（`tests/test_shapes.py`，12 项）

- 几何：贝塞尔端点/中点解析解（B(0.5)=(P0+3C1+3C2+P3)/8）、密度随长度增长；
  弧的 0°/90°/−90° 落点、一圈夹取、`sweep=0` 与零宽高报错；折线去重与校验；
- 解析：三种写法等价、缺键报错；
- 编译：shape 类型/op 下标/坐标 round(2)；
- 渲染：矢量路**颜色数 > 40**（抗锯齿中间色，证明是矢量不是硬边）；
  像素路含三色但颜色数显著更少（硬边）；曲线越界进 `bounds_warn`；
- CLI：`annotate --ops-file` 端到端 `backend: gdi+`。

全套 **154 项**通过。

## 6. 边界

- **不做**：自由手绘（要交互）、闭合贝塞尔路径（`closed:true` 可后加）、
  二次贝塞尔（三次已足够；二次可退化为共线控制点）；
- 弧线只支持**椭圆弧**（不做圆弧专用语法：给正方形外接框即是圆弧）；
- 极长的曲线（>2000px）采样点会到上限 128，理论上在超高分屏上可能
  看出轻微折线，实际输出是位图，肉眼不可辨。
