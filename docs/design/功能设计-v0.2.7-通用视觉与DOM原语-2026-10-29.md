# 功能设计 v0.2.7 —— 通用视觉与 DOM 原语（不是验证码）

> 日期：2026-10-29　基线：v0.2.6（工作区）　状态：设计 → 实施
> 动机：用户与 Ashot 的分工讨论——**不做验证码 solver**，只补三个
> 「非验证码专用、但任何验证码流程都要用」的通用原语：
> ① 图像指纹/差异　② 元素矩形+可见性　③ iframe 坐标映射。
> 有了它们，调用方可以自己拼「快照 → 指纹 → 算偏移 → 拖 → verify」，
> Ashot 永远不需要知道"验证码"三个字。

## 1. 调研结论（2026-10-29，带出处）

### 1.1 图像指纹/差异

| 来源 | 结论 | 我们怎么用 |
|---|---|---|
| [imagehash](https://github.com/JohannesBuchner/imagehash)（PyPI 4.x，常用感知哈希库） | `dHash`=缩到 9×8 灰度后比较相邻像素（64 bit）；`aHash`=8×8 与均值比较；`pHash`=DCT 低频 | 取 **dHash + aHash**（无 DCT、纯整数运算，标准库可写）；再加 **sha256** 做"是否同一文件"的精确判据 |
| [pixelmatch](https://github.com/mapbox/pixelmatch)（截图 diff 事实标准） | YIQ 颜色距离 + `threshold`（0~1）+ **抗锯齿像素检测**（避免字体抗锯齿造成假差异） | 取「YIQ 距离 + threshold」，**AA 检测不做**（需要邻域启发式，纯 Python 成本高），文档写明"字体抗锯齿可能造成少量假差异" |
| 实践要点 | 尺寸不同的两张图不能直接比 | 尺寸不同→只比重叠区，收据亮 `size_mismatch` + 各自尺寸 |

### 1.2 元素矩形与可见性

| 来源 | 结论 | 我们怎么用 |
|---|---|---|
| [MDN: Element.checkVisibility](https://developer.mozilla.org/en-US/docs/Web/API/Element/checkVisibility)（**2024-03 起 Baseline**） | 返回"是否可能可见"；选项 `opacityProperty`/`visibilityProperty`/`contentVisibilityAuto`（旧名 `checkOpacity`/`checkVisibilityCSS`）；**明确不检查视口外/被遮挡** | 可见性判定用它；**视口交集**自己算；**遮挡**用 `elementFromPoint(中心)` 判 |
| 实践补充 | 元素可能在视口外、被浮层盖住、`pointer-events:none` | 收据同时给 `visible`/`in_viewport`/`occluded`/`pointer_events`，不合并成一个 bool |
| 坐标 | `getBoundingClientRect` 是**视口 CSS 像素**（含滚动影响） | 收据给 rect + center + `dpr` + `scrollX/Y`；调用方点击用 CSS 坐标，不用截图坐标 |

### 1.3 iframe 坐标映射（本机实测，非文档）

用 Playwright 自带 Chromium 开 CDP 实测：

- `DOM.getBoxModel` 返回的是**主框架视口坐标系**的 CSS 像素（主页面 `scrollTo(0,300)` 后同一 iframe 的 y 从 500 变 200），且 `model.border` 是含边框的外框、`model.content` 是去掉 border 的内容框（实测 border=4 时 104 vs 100）。
- `DOM.describeNode` 对 iframe 节点返回 **`frameId`**，与 `Page.getFrameTree` 的 id 一致——这是"元素 ↔ frame"的桥。
- `Page.createIsolatedWorld(frameId)` 拿到该 frame 的 `executionContextId`，再用 `Runtime.evaluate(contextId=...)` 就能在**跨域 frame 内部**求值（实测拿到子 frame 的 `getBoundingClientRect`）。
- 因此坐标合成公式：`主视口坐标 = iframe 内容框原点（getBoxModel.content）+ 子 frame 内元素视口坐标`；子 frame 内部有滚动时，元素 `getBoundingClientRect` 已含其滚动影响，直接相加即可。
- **边界（实测踩到）**：跨站（OOPIF）子 frame 不出现在主会话的 `Page.getFrameTree.childFrames` 里，需要 `Target.attachToTarget` 建独立会话——本版**不做**，遇到时如实报 `oopif_unsupported` 并给出 iframe 自身矩形。

## 2. 范围

**做（三个原语）**：

1. `vision.py`：`sha256` / `dhash` / `ahash` / `hamming` / `digest` / `diff`（可输出差异图）。
2. `dom.py`：`element_rect(selector)`（可见性/视口/遮挡/pointer-events/中心点）；
   `frame_element_rect(iframe_selector, selector)`（同源任意深度 JS 递归；
   跨域单层走 CDP；OOPIF 如实报不支持）。
   `frames()`：frame 树 + iframe 自身矩形。
3. CLI/MCP 双脸各加 4 个入口。

**不做**：验证码识别/OCR/点选/行为验证；点击本身（已有 `cdp-click/drag`）；
全站 DOM 树导出；OOPIF 深链。

## 3. API 契约

### 3.1 库

```python
vision.digest(png) -> {"sha256", "dhash": "0x…", "ahash": "0x…", "w", "h"}
vision.hamming(a_hex, b_hex) -> int          # 不同 bit 数
vision.diff(a_png, b_png, threshold=0.12, make_image=False)
  -> {"same": bool, "changed_px", "total_px", "ratio",
      "bbox": [x,y,w,h] | None, "size_mismatch": bool,
      "dims": [[w,h],[w,h]], "image": png_bytes|None}
```

- `threshold`：YIQ 归一化距离（0~1），缺省 0.12（≈像素肉眼可见）；
- 尺寸不同：只比重叠区，`ratio` 以重叠区为分母，`size_mismatch=True`；
- `same=True` 当 `ratio==0`（阈值内视为未变）。

### 3.2 DOM

```python
dom.element_rect(ws, selector, scroll=False) -> {
  "found": True, "tag", "text",
  "x", "y", "w", "h", "cx", "cy",        # 视口 CSS 像素
  "visible", "in_viewport", "occluded", "pointer_events",
  "dpr", "scroll_x", "scroll_y",
  "visible_ratio"                        # 元素与视口交集面积比
}
```

- `scroll=True`：先 `scrollIntoView({block:"center"})` 等两帧再量；
- `visible` 用 `checkVisibility({opacityProperty, visibilityProperty, contentVisibilityAuto})`，旧浏览器回退到 `offsetParent` + computedStyle；
- `occluded` 用 `elementFromPoint(cx,cy)`：命中自身或后代=未遮挡。

```python
dom.frame_element_rect(ws, iframe_selector, selector) -> element_rect 形状 +
  {"frame_chain": [{"selector", "rect", "cross_origin"}], "cross_origin": bool}
dom.frames(ws) -> [{"id","url","parent_id","depth"}]
```

- 同源：主文档 JS 递归 `contentDocument`（支持嵌套），一次求值；
- 跨域（同进程）：`DOM.describeNode`→`frameId`→`createIsolatedWorld`→
  子 frame 求值 + `DOM.getBoxModel` 内容框原点相加；
- OOPIF：抛 `RuntimeError("oopif_unsupported…")`，错误里带 iframe 矩形。

### 3.3 CLI / MCP

| CLI | MCP | 说明 |
|---|---|---|
| `hash <png> [--algo sha256|dhash|ahash]` | `ashot_hash(image, algo="dhash")` | 收据含全部三种 + 尺寸 |
| `diff <a> <b> [--threshold] [--out diff.png]` | `ashot_diff(a, b, threshold=0.12, out=None)` | 收据含 ratio/bbox |
| `element <selector> [--scroll] [--port]` | `ashot_element(selector, scroll=False, port=None)` | 视口 CSS 坐标 |

| — | `ashot_frame_element(iframe, selector, port=None)` | 跨 iframe 取矩形 |

## 4. 算法细节

- **dHash**：RGBA → 9×8 灰度（盒式降采样，面积平均）→ 每行 8 次相邻比较
  → 64 bit；**aHash**：8×8 灰度 → 与均值比较；比较用 `hamming`。
- **diff**：逐像素 RGB→YIQ（`Y=0.299R+0.587G+0.114B` 等权重近似），
  距离 `sqrt(ΔI²+ΔQ²)` 归一化到 0~1（pixelmatch 同源公式）；超阈值即
  `changed`；bbox 取变化像素包围盒；差异图=原图压暗 60% + 变化像素涂红。
- 纯标准库：复用 `annotate._decode_png` 解码，`output.rgba_to_png` 编码。

## 5. 测试锁

1. `digest`：同图同 hash；改一像素 dHash 变、sha256 变；dHash 对缩放/亮度
   平移稳定（同一图形降采样后 hamming ≤ 6）。
2. `diff`：同图 `same=True, ratio=0`；单像素变化 ratio≈1/像素数、bbox 精确；
   尺寸不同 `size_mismatch=True` 且不崩；`make_image` 出图可解码。
3. `element_rect`：桩 `call` 返回合法结果→字段齐全；`found:false`→
   如实报错；JS 模板含 `checkVisibility`、`elementFromPoint`、`innerWidth`。
4. `frame_element_rect`：桩两段（子 frame evaluate + getBoxModel）→
   坐标相加正确；`oopif` 路径抛可读错。
5. CLI 子进程：hash/diff 退出码 0、收据 JSON 可解析。
6. MCP schema：20 工具、新工具参数类型正确。

## 7. 风险与边界

- 字体抗锯齿会带来少量假差异（未做 pixelmatch 的 AA 检测）；
- 跨站 OOPIF 不支持（明确报错，不静默）；
- `elementFromPoint` 只能判中心点遮挡，细长元素可能漏判；
- `checkVisibility` 的旧浏览器回退是近似判定，收据带 `visibility_source`；
- 不承诺"能点中"——只如实给几何与可见性，点不中是调用方策略问题。
