## 0. 一句话

把 Ashot 从「Windows 桌面截图工具」扩成「**跨平台、宿主无关**的捕获
工具」：Mac 用系统自带 `screencapture`/`sips`，浏览器用纯标准库 CDP
客户端直连任何 Chromium（无头/有头/任何宿主启动的），Windows 补按
HWND 的后台窗口捕获。

## 1. 需求与动机

1. **Mac mini 可用**：用户明确要求。现状=捕获/矢量渲染 Windows 专属
   （GDI/PowerShell/System.Drawing），标注核心（像素画布/字体/字库/
   show/MCP 脸）本就纯标准库跨平台。
2. **跨宿主通用**：用户在 Workbuddy/Codex/DeepSeek harness 等多处使用
   ——MCP stdio 脸本就通用，但 v0.1.11 的浏览器捕获路线借了 ZCode 的
   browser-use 技能（宿主专属），被用户定性「局限死了」。正解=CDP 做
   进 Ashot（宿主无关）。
3. **被遮挡窗口 / 无头浏览器**（用户原话两问，§2 直答）。

## 2. 两个效果问题直答（调研结论）

### Q1 软件界面被挡在后面一层，能截图吗？

**能，两家都有正解，遮挡本身不构成障碍**：

| 平台 | 机制 | 说明 |
|---|---|---|
| Windows | `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)` | 让窗口自己把自己画进内存位图——**不要求前台/可见/未被遮挡**。`PW_RENDERFULLCONTENT`(0x2, Win8.1+ 未公开常量)是命门：没有它 GPU 渲染窗口（Chrome/ZCode 全是）出黑图 |
| macOS | `screencapture -l<CGWindowID> -o` | 抓窗口自己的缓冲（CGWindowList 体系），与遮挡无关；`-o` 去阴影；Catalina+ 需授予**屏幕录制权限** |

**边界（两家相同）**：真**最小化**窗口可能拿旧帧或空图——对策=临时恢复
（Windows: `SW_SHOWNOACTIVATE`+`DWMWA_TRANSITIONS_FORCEDISABLED` 禁
动画不抢焦点，抓完复原；Mac: 同思路），收据如实标注是否动过窗口；
DRM 保护内容（视频区）两家都拒渲染，如实亮牌。

### Q2 按窗口去找，无头浏览器能截图吗？

**不能按窗口找——但能截，走 CDP**。无头浏览器没有窗口（无 HWND/
CGWindowID），「按窗口找」在无头场景无对象。正解 = CDP 的
`Page.captureScreenshot`：对**无头/有头通吃**，且支持
`captureBeyondViewport` 全页截图（视口外的也截）。

```
流程（全部纯标准库可实现）：
GET http://127.0.0.1:<port>/json/list     → 各 target 的
  webSocketDebuggerUrl / title / url / type
GET .../json/version                      → browser 级 ws 端点
WebSocket 连接 page 级 URL（裸 WS：握手+帧编解码，见 §4.3）
发送 {"id":1,"method":"Page.captureScreenshot",
      "params":{"format":"png","captureBeyondViewport":true}}
→ result.data (base64) → PNG 字节
```

**端点发现两式**：固定 `--remote-debugging-port=9222`；或
`--remote-debugging-port=0` 让浏览器挑空闲端口并写
**`DevToolsActivePort` 文件**（user-data-dir 下，首行=端口，次行=
browser target 路径）——Cypress 等的推荐做法，免端口冲突。

## 3. 调研实录（2026-10-28，WebSearch）

- **macOS `screencapture`**：`-l<windowid>` 按 CGWindowID 抓窗口、
  `-o` 去阴影、`-x` 静默、`-c` 进剪贴板；Catalina+ 需屏幕录制权限
  （缺权限=拍到桌面而非窗口，收据须亮牌）；窗口 ID 随应用重启变化，
  每次现查（osascript 枚举 CGWindowList）。
- **macOS `sips`**：`--resampleWidth N`（等比）、`-s format jpeg -s
  formatOptions 85`（质量）——preview/缩图的 Mac 路径，与 Windows
  System.Drawing 同为「spawn 系统工具」模式。
- **CDP 裸连（无 Puppeteer）**：`/json/list` → ws → JSON 命令 →
  base64 data；`websocket-client` 是第三方，**纯 stdlib WebSocket
  客户端可行且已有先例**（awsearch r47 实测）。
- **DevToolsActivePort**：`--remote-debugging-port=0` + 读文件免端口
  冲突；「file doesn't exist」=浏览器没起来/崩了的信号（如实报）。
- **PrintWindow 实战坑（Win）**：① 向目标发 WM_PRINT，目标挂则调用
  挂（微软明示 UI 线程警告；Win11 有 20s+ 慢报告）→ 放 PS 子进程 +
  timeout，挂死隔离现成；② GPU 窗口偶发黑图 → 重试 + all_black 检测
  （现成）；③ 最小化 → §2 恢复三步（新代码）；④ 合盖/屏关旧帧 →
  如实亮牌。
- **WGC（Windows.Graphics.Capture）**：GPU 直取高帧率无视遮挡，但
  WinRT 互操作重 + 边框策略 + 「抓到屏幕区域而非窗口内容」的坑——
  静态截图不采用，留窗口录像需求（ALrec 领域）。
- **headless 命令行直截**：`msedge --headless=new --screenshot=out.png
  --window-size=1280,800 <URL>`——零依赖快捷路，但=全新会话无 cookie
  （带 --user-data-dir 才有）、只抓视口；作为 `cdp-shot` 的轻量补充
  评估，不单列一批。

### 4.0 导入守卫（审计 P1-1，**前移进批1**——不修批1 在 Mac 直接翻车）

**现状实锤**：`capture.py:20-21` 在**模块顶层**执行
`ctypes.windll.user32`——Mac 上 import 即 AttributeError；而 cli/mcp
无条件 import capture → **批1 的 cdp 命令在 Mac 连启动都不行**。

- 批1 就地修：capture.py 顶层 windll 访问改为**函数内懒加载**（或
  `sys.platform` 守卫）——一行级改动，批1 必做；
- 批2 落地时把 capture.py 瘦身为纯分发壳（桌面路下沉 capture_windows）。

### 4.1 平台抽象

```

├── capture.py            → 保留：Windows GDI 桌面路 + 分发壳
│                            （sys.platform 探测，Mac 上如实报不支持桌面路）
├── capture_windows.py    → 新：PrintWindow/EnumWindows 窗口捕获（批3）
├── capture_mac.py        → 新：screencapture 全屏/窗口/区域（批2）

├── output.py             → preview_jpeg 平台分流：System.Drawing / sips

                             顶层硬编码 powershell 且不吞异常，Mac 上
                             fonts/ashot_fonts 全挂）——批2 加平台分流
                             （Mac=sips 无字库概念，用 system_profiler
                             SPFontsDataType 或如实报不支持）；clip_png

- **Mac 矢量渲染**：GDI+ 不可用 → 自动落**像素后端**（backend 收据

  逻辑已核对，Mac 上此声明现有代码即成立）；CoreGraphics 矢量路列
  远期。**[审计 P2-4] Mac 像素后端 text 走 8×16 点阵仅 ASCII——
  中文标注在 Mac 像素路不可用**，收据必须显式亮牌（旗舰特性损失，
  不许静默）。

  输出（需 stat）、formatOptions 质量语义与 Encoder.Quality 不同、
  有独立色彩管理（同图字节差异大）——批2 需重写梯次循环。

### 4.2 CDP 客户端（批1，cdp.py）

- HTTP 面：`urllib` GET `/json/list`、`/json/version`（零新依赖）。
- WebSocket 面：**纯 stdlib**——socket 连接 + HTTP Upgrade 握手
  （Sec-WebSocket-Key = base64(16 随机字节)）+ 帧编解码（客户端帧必须
  masked；CDP 只用 text 帧 + 服务端 unmasked 帧；7/16/64-bit 长度）。
  参考先例：awsearch r47（纯 stdlib WS 已实测）。
- 命令：`Target.getTargets`（browser 级）/ `Page.captureScreenshot`
  （page 级，`captureBeyondViewport` 全页——Chrome 90+，协议默认已
  true，显式传 true 无害 [审计 P3-12]）。
- 连接目标三式：`--port 9222` 固定；`--port 0 --user-data-dir D` 读
  DevToolsActivePort；直接给 `--ws-url`。
- **发现已运行浏览器（审计 P1-2，跨宿主诉求的核心 UX）**：宿主
  （Workbuddy/Codex 等）拉起的浏览器，Ashot 按 `discover` 策略自动找：
  ① 枚举进程命令行提取 `--remote-debugging-port=N` 与
  `--user-data-dir=D`（Win: `Get-CimInstance Win32_Process`（PS 子
  进程）；Mac: `ps -axo command=`）→ ② 有 user-data-dir 读其
  DevToolsActivePort → ③ 扫常见端口（9222-9229）探活 `/json/version`
  → ④ 全空则如实报「未发现」，指引用户带 --port。cdp-tabs/cdp-shot
  均收 `--discover`（缺省=显式参优先，无参时才 discover）。
- **[审计 P2-5] Chrome 136+ 默认 profile 拒绝远程调试**（Google 因
  劫持滥用收紧；150 有「端口在听但 /json/version 404、
  DevToolsActivePort 不写」实例）——**前置条件写死**：实弹/文档一律
  非默认 `--user-data-dir`；收据遇 404 亮牌 `default_profile_denied`
  +指引。
- **WebSocket 客户端规格（审计 P2-11 补全收侧）**：
  - 发侧：握手（Sec-WebSocket-Key=base64(16 随机字节)）、客户端帧
    必须 masked、长度三态（7/16/64-bit）、不协商 permessage-deflate；
  - 收侧：**半包循环 recv**（大消息一次收不满）、**continuation 帧
    （opcode 0）分片重组**（几 MB base64 截图大概率分片到达）、
    **服务端 ping(0x9) 必须回 pong(0xA)**（不回可能被断连）、close
    帧回礼、socket timeout（挂着的浏览器不卡死客户端）。
- **安全**：CDP 端点=完全控制浏览器，只连 127.0.0.1；文档明示暴露
  风险（Google Chrome 136 收紧即因滥用）；`--remote-debugging-pipe`
  （fd 3/4，无本地端口面）记录为未来自拉浏览器时的更优解 [审计
  P3-14]；不提供远程绑定。

### 4.2.2 输入事件注入（2026-10-28 用户需求追加：滚轮/回车/组合键/拖拽）

CDP `Input.*` 域，批1 追加实现（纯命令派发，复用 §4.2 WS 层）：

- **鼠标** `Input.dispatchMouseEvent`：`mousePressed`/`mouseReleased`/
  `mouseMoved`/`mouseWheel`（deltaX/deltaY 滚动）；坐标=CSS 像素。
- **键盘** `Input.dispatchKeyEvent`：可见字符=**`rawKeyDown`+`char`
  双发**（rawKeyDown 带 code/windowsVirtualKeyCode 无 text，char 带
  text——只发 rawKeyDown 页面不产生输入，只发 char 不触发快捷键）；
  控制键（Enter/Tab/Escape/Backspace/方向键）=keyDown+keyUp；
  **组合快捷键**=`modifiers` 位掩码（**Alt=1, Ctrl=2, Meta=4,
  Shift=8**，可加和）+ 按住序（modifier keyDown → 主键 → keyUp）。
- **拖拽**=mousePressed→mouseMoved×N（插值步进）→mouseReleased 序列
  （无独立 drag 命令，就是事件序列）；另 `Input.insertText`（整段
  文本直插，不走键击）。
- **诚实边界**：注入的是「浏览器以为是用户」的事件（CDP 事件
  isTrusted=true，页面层无法区分）；对浏览器外无效；需目标标签页
  持焦点。

**新面**：CLI `cdp-key`（--key/--text/--modifiers）/`cdp-wheel`
（--dx/--dy）/`cdp-click`（--x/--y/--button）/`cdp-drag`（--from
--to --steps）；MCP `ashot_cdp_key/cdp_wheel/cdp_click/cdp_drag`
（同参）。全部复用 §4.2 发现与连接层。

**测试锁**：键序列构造纯函数单测（rawKeyDown+char 双发/modifiers
位/控制键双发）；拖拽事件序列（按下→插值 moved→释放）；实弹
headless Edge（滚轮后 scrollY 变化、Enter/文本注入、组合键）。

### 4.2.3 人类化鼠标轨迹（2026-10-28 用户需求追加，v0.2.4）

**需求原话**：「鼠标移动轨迹，不要瞬间移动到位的，移动过程/路径要
稍微带点抖动，模拟人类一样，但要比人类快。」

**业界配方**（WebSearch 2026-10-28：pyautogui 贝塞尔 SO 经典答/
human_mouse 库/RTILA 反检测文/IJIRT 论文）：三次贝塞尔（随机控制
点）+ 缓动速度曲线 + 逐点微抖动 + 偶发过冲回正。

**实现**（cdp.py `human_move_events` / `move_along`，纯函数可单测）：

- **三次贝塞尔**：两个控制点取连线垂直方向随机弓偏（距离的
  10%~25%，随机正负）——每条轨迹都是不同的弧线；
- **缓动**：smoothstep（te=t²(3-2t)）——慢起、快中、慢收；
- **微抖动**：每点随机偏移（缺省 ±2px），幅值乘 `sin(πt)` fade——
  中段最抖、两端收敛；**首尾精确落点**（点击必须准）；
- **步数自适应**：按距离 8~28 步（拖拽按住态 10~40）；**比人快**：
  无真实延时（CDP 派发间隔由网络决定，几十 ms 走完人要 300ms 的路）；
- `seed` 可复现（测试/调试）；`human=False` / `--teleport` 逃生门
  退回瞬移/直线旧行为。

**接入面**：cdp-drag（按住态轨迹）、cdp-click/cdp-dblclick（接近
轨迹到位再按下）——缺省 human=True；MCP 同名三工具同步 `human`/
`seed` 参数。

**实弹形态验证**（headless Edge mousemove 回读）：起点/终点精确、
中段最大偏离直线 14.9px（弧线）、前段点距 1→5→9→12→15 递增（缓动
加速）——三个反检测特征齐活。

**诚实边界**：这是「形态像人」（轨迹几何），不是「时序像人」（CDP
派发无人类级延时；需要时序拟真属于未来 batch）。轨迹随机≠不可检测
（高级风控可从速度分布/事件间隔统计辨识）——如实入档不夸大。

> **v0.2.5 覆盖注记（2026-10-28）**：上段「时序拟真属于未来 batch」
> 已落地——本版「无真实延时」被 Session 化派发 + 事件级 `_delay_ms`
> 节奏（fast/normal/**captcha** 三档，拖拽 900~2600ms 可调）取代；
> 且拖拽缺省改为**受轨道约束**轨迹（弓形按距离放大会让 520px 拖拽
> 纵向漂 50px，滑块脱轨——`constrained=False` 才保留自由弧线）。
> 详见《功能设计-v0.2.5-滑块拖拽约束与节奏-2026-10-28.md》。
> 「轨迹随机≠不可检测」的诚实边界仍然成立。

**测试锁（v0.2.4）**：seed 确定性、首尾精确落点、步数自适应边界、
teleport 旧行为、拖拽轨迹中段偏移>1px、schema human/seed 参数。

### 4.3 窗口捕获（批3，capture_windows.py）

- `wins`：`EnumWindows` + `GetWindowText`/`IsWindowVisible`/
  `IsHungAppWindow` 预检 + **`DwmGetWindowAttribute(DWMWA_CLOAKED)`
  排除挂起 UWP**（无有效渲染面→空/黑图 [审计 P2-7]）→ 列表
  （hwnd/标题/PID/可见）。
- `win-shot`：PrintWindow(`PW_RENDERFULLCONTENT`) in **PS 子进程**
  （挂死隔离 + timeout）→ all_black 重试一次 → 最小化时
  SW_SHOWNOACTIVATE 恢复→抓→复原（收据标 `window_restored: true`）。
  **[审计 P2-6] PS 子进程 Per-Monitor DPI**：DPI-unaware 子进程的
  GetWindowRect 被虚拟化→错尺寸/发糊——PS 脚本内
  `SetProcessDpiAwareness`（或用 GetClientRect+DPI 换算），测试锁
  高 DPI 屏。
- 目标选择：`--title 子串` / `--hwnd N`。
