# 功能设计 v0.7.4 —— fill：色块填充

> 日期：2026-10-31　版本：v0.7.4　基线：v0.7.3（commit `c145464`）
> 缘起：用户用 annotate 画简笔画风景，成品「很丑」——**填不了色块**。
> 缺陷确认：ops 里写 `fill` 会被字段白名单当拼写错误直接拒掉；
> 但实心箭头早已在用填充多边形（`t:"fill"` + ps1 `FillPolygon`），
> **填充引擎其实存在，只缺用户侧开关**。用户裁决：加。

---

## 0. 一句话

给闭合形状（rect 含 radius / ellipse / curve / polyline / arc）开一个
`fill` 字段：指定填充色，**先填后描**（描边压在色块上）；颜色支持
`#RRGGBBAA` 半透明；填充规则=**非零环绕（Winding）**，矢量路
（GDI+）与像素降级路（扫描线）同一口径。实现复用既有的
`t:"fill"` 指令与 ps1 `FillPolygon` 分支——**渲染端几乎零新概念**。

## 1. 调研（一手文档，2026-10-30）

> 网络备注：本机直连 learn.microsoft.com 的 API 页返回 135 字符 JS 壳
> 或 404（via-browser 也一样），raw.githubusercontent.com 被 RST。
> 权威原文改从 **dotnet/dotnet-api-docs 的 XML 源文件**取
> （api.github.com contents API + `Accept: application/vnd.github.raw+json`，
> `xml/System.Drawing/Graphics.xml`，1.4MB 存本地提取成员段）。

| 来源 | 结论 | 我们怎么用 |
|---|---|---|
| [Graphics.FillPolygon 重载族 (dotnet-api-docs `Graphics.xml`)](https://github.com/dotnet/dotnet-api-docs/blob/main/xml/System.Drawing/Graphics.xml) | `FillPolygon(brush, pts)` 之外有 `FillPolygon(brush, pts, FillMode)`；**"The default mode is Alternate"**（偶奇规则） | 不指定=偶奇，与直觉/ SVG 缺省不符——ps1 显式传 `FillMode::Winding`（非零环绕） |
| Graphics.FillPie 成员文档 | 扇区=两条半径线夹出的 pie 段（外接矩形 + start/sweep 度） | 弧的 fill 语义对齐：Python 侧构造 **圆心→弧→闭合回圆心** 的点列，不直接调 FillPie（见 §1.1） |
| Graphics.FillClosedCurve 成员文档 | 闭合基数样条区域填充（Tension 参数） | 未采用——curve 已是采样折线，多边形闭合语义足够 |
| Graphics.CompositingMode / SolidBrush | 缺省 `SourceOver`=按 alpha 混合；带 alpha 的 SolidBrush 直接得到半透明填充 | `#RRGGBBAA` 直接喂 SolidBrush，无需手写混合（矢量路） |
| [MDN fill-rule](https://developer.mozilla.org/en-US/docs/Web/SVG/Attribute/fill-rule) | SVG 缺省 `nonzero`（非零环绕）；`evenodd` 需显式声明 | Winding 与 SVG 缺省一致；凹/自交多边形两路结果一致 |

### 1.1 一个必须记住的 .NET 坑

`ColorTranslator.FromHtml` 的 8 位 HTML 色是 **#AARRGGBB（alpha 在前）**，
与我们约定的 **#RRGGBBAA（alpha 在后）相反**。ps1 里对 9 字符色值
手动按 alpha-in-last 解析 `Color.FromArgb(a,r,g,b)`，不走 FromHtml——
否则透明度通道会整通道错位（红蓝对调、alpha 当红值），且不会报错。

### 1.2 为什么仍走「点列 + FillPolygon」而不是 FillPie/FillClosedCurve

与 v0.4.1 曲线三件同一条理由（设计文档 §7.6.4）：
1. **几何全在 Python（可单测），PS 零形状数学**——扇形点列在
   `vector.compile_ops` 里构造，单测直接断言「fill 首点=圆心」；
2. 渲染脚本只多两件事（8 位色解析 + 传 FillMode），降级路
   `fill_polygon` 与矢量路共用同一套点列语义；
3. `bounds_warn`、op 下标 `i`、降级判定全部零改动复用（fill 形状
   走既有的按点列算 bbox，`annotate_gdi.py:141` 早已对 `t:"fill"`
   不加半笔宽）。

## 2. 契约

| 项 | 规则 |
|---|---|
| 适用范围 | 闭合形状：`rect`（含 `radius` 圆角）/ `ellipse` / `curve` / `polyline` / `arc` |
| 字段 | `"fill": "#RRGGBB"` 或 `"#RRGGBBAA"`（alpha 在后） |
| 顺序 | 编译为 `fill` 形状在前、`stroke` 在后——**描边压在色块上**（同 op 两形状共用 `i`） |
| arc 语义 | **扇形**：圆心 → 弧采样点 → 闭合回圆心（FillPie 同语义）；stroke 仍是弧本身 |
| curve/polyline 语义 | 多边形自动闭合（末点连回首点），描边不闭合（原语义不变） |
| 拒收 | `line`/`text`/`arrow`/`step`/`number`/像素 ops 给 fill → apply_pad 报错（无内部可填）；`fill` 之外的拼错照旧报错 |
| 颜色 | `fill` 收 6 或 8 位 hex；`color` 只收 6 位（像素降级路描边/文字不做 alpha，8 位 color 入口报错，避免两路不一致）；4 位缩写**不支持** |
| 混合 | alpha<255 source-over：矢量路 SolidBrush 原生；像素路 fill_polygon 手写混合（降级路唯一混合点） |
| 填充规则 | **Winding（非零环绕）**：GDI+ 官方明说缺省是 Alternate（偶奇），必须显式传；像素扫描线同用 non-zero。实心箭头多边形简单无自交，改 Winding 行为不变 |

**不要填充描边怎么办**：把 `color` 给成与 `fill` 同色即可（一期不加
`stroke:false`，见 §6）。

## 3. 实现（改动点与行号）

```
ashot/vector.py
  _ALLOWED_KEYS 加 "fill"（白名单单源，两路入口都过 apply_pad）
  apply_pad：fill 只允许 _FILL_KINDS，其余 kind 报错（单源校验）
  _hex：6→6/8 位
  _fill(pts,color,oi)：t:"fill" 指令（实心箭头内部同款提为公共 helper）
  compile_ops：rect/ellipse/curve/polyline 带 fill → 先 _fill 后 _stroke；
               arc → _fill([圆心]+弧点列)（parse_arc 参数提出来复用）
ashot/_gdi_render.ps1
  色值 9 字符（#RRGGBBAA）手动 FromArgb(a,r,g,b)——绕开
    ColorTranslator 的 #AARRGGBB 坑（§1.1）
  fill 分支：FillPolygon(..., [FillMode]::Winding)
ashot/annotate.py（像素降级路）
  Canvas.fill_polygon：扫描线 + 非零环绕（带方向计数出 span），
    像素中心 (xx+.5, yy+.5) 落 [s,e) 判定；alpha<255 source-over 混合
  _color_a：#RRGGBB[AA] → (rgb, alpha)
  annotate_png：rect（复用 vector._rect_path，圆角矩形填充轮廓与描边
    一致）/ellipse（vector._ellipse_path）/curve/arc/polyline 先填后描
ashot/mcp.py / SKILL.md / CHANGELOG：描述同步；版本 0.7.3→0.7.4
```

关键设计点：

- **两路口径一致靠「同一规则」而非「同一代码」**：矢量路把 non-zero
  交给 GDI+（Winding），像素路扫描线自己实现 non-zero（`wind != 0`
  才算内）。凹/自交多边形（星形、回头折线）两路同色——测试实锁。
- 弧扇形圆心用 `parse_arc` 的返回参数（`(x+w/2, y+h/2)`），不重读 op
  键——弧的三种角度写法（start/sweep/end）自动兼容。
- 圆角矩形填充直接复用 `_rect_path(radius)` 采样轮廓：填充区与描边
  区共享同一条轮廓，corner 不会出现填充缩进/溢出。

## 4. 测试（`tests/test_fill.py`，10 项）

- 编译：五类形状 fill+stroke 顺序（fill 在前）、共用 op 下标、点数≥3；
  arc 扇形**首点=圆心** [50,50]；
- 拒收：line/text 给 fill → ValueError；
- `_hex`：8 位过、3 位/非法 hex 抛；
- 渲染两路：实心 rect 内部**纯填充色**（gdi+ 与 pixel 都验）、块外
  仍背景；半透明 `#FF000080` 两路都出中间色（红通道严格介于
  背景与饱和红之间、绿蓝被拉低）；
- fill+同色描边重叠：两路内部纯填充色（Winding 不吞内部）；
- 凹多边形（自交点列）：两路内点都出墨（non-zero parity）；
- `bounds_warn`：填充矩形越右界照样亮牌（fill 形状进 bbox 统计）；
- CLI 端到端：`annotate --ops-file` → `backend: gdi+`、中心像素=填充色。

全套 **205 passed, 6 skipped**（v0.7.3 的 192 + 本批 13，零回归）。

## 6. 边界（刻意不做）

- **无 `stroke:false`/`outline:none`**：一期用「color 同 fill」代替；
  真需求出现再加显式开关（字段面最小化纪律）；
- **不加独立 opacity/alpha 字段**：透明度只走 `#RRGGBBAA`（单源）；
- **不做渐变/图案填充**（GDI+ LinearGradientTextureBrush 一类）——
  标注工具语境下是 scope creep；
- **不开放 FillMode 选择**：固定 Winding；要偶奇效果请自己拆多边形；
- **像素降级路的 fill 是硬边 + 手写混合**（收据 `backend=pixel` +
  `degrade_reason` 已亮牌，按既有契约不算隐藏缺陷）；
- text/step/number 不加背景框（历史裁决「text 无圆底」，v0.1.3 P1-B）。

## 7. 审查修正（2026-10-31）

- **8 位 color 只允许 fill**：像素降级路的描边/文字仍是覆盖式直写，
  8 位 color 会让 GDI+（半透明）与像素路（不透明）出两种结果——
  `apply_pad` 入口拒绝，`_stroke` 二次防御。
- **透明底半透明 fill**：`fill_polygon` 改为按目标 alpha 的 source-over
  （`oa = a + ba*(1-a)`，RGB 除以 oa），透明底上 `#FF000080` 两路都是
  `(255,0,0,128)`；alpha=00 为 no-op，不再把像素刷成不透明。
- **退化 fill**：`_fill` 点数 <3 直接报错，绕过 apply_pad 直接 compile_ops
  也不会产出两点填充。
- 新增 3 条回归（stroke alpha 拒绝、透明底 alpha 两路一致、alpha=00 no-op）。
