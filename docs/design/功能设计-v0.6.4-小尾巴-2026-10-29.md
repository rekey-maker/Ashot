# 功能设计 v0.6.4 —— 三个小尾巴（性能/测试/哨兵）

> 日期：2026-10-29　版本：v0.6.4　基线：v0.6.3（commit `d2c3528`）
> 缘起：v0.6.2/v0.6.3 复审留下的三条 P2——scrollables 多一次求值、
> 真浏览器行为没有 pytest 锁、`__resolved__` 可被客户端伪造。

## 1. 调研（2026-10-29）

| 问题 | 查到的做法 | 取舍 |
|---|---|---|
| 怎么判"可滚动" | [MDN scrollHeight](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollHeight) 官方示例：`scrollHeight > clientHeight` **且** `getComputedStyle(el).overflowY` ∈ {scroll, auto} | 已在 v0.6.3 采用；本版只做**求值合并**，不换判据 |
| 能不能一次拿齐视口+滚动容器 | CDP `DOMSnapshot.captureSnapshot` 返回布局树（含滚动信息），但 JSON 巨大、要把 nodeId 映射回 DOM | **不采用**：对"列几个可滚容器"太重；仍用一条 `Runtime.evaluate` |
| 浏览器 E2E 怎么写 | [pytest-playwright](https://playwright.dev/python/docs/test-runners) 提供 `page/browser` fixture，`--browser-channel msedge` 可跑 Edge | **借模式不借依赖**：用本机 Edge/Chrome + 自家 `ashot.cdp` 起临时 profile，零新增依赖 |
| 怎么防"内部标记被伪造" | Python 常用 **sentinel**（模块私有对象）区分"内部状态"与"用户输入"；JSON 只能产出普通 dict | **采用**：`ResolvedOp(dict)` 子类，`isinstance` 判定，JSON 无法伪造 |

## 2. 实现

### 2.1 scrollables 并进 layout 的同一次求值

- `cdp.layout(ws, include_scrollables=True)`：把 `dpr/scrollX/scrollY` 与
  `scrollables` 合成**一条** `Runtime.evaluate`（原来 layout 一次 +
  scrollables 一次，`cdp-view` 还各自开 WS，共 3 次往返）。
- `cdp-view` 现在 2 次协议往返（`Page.getLayoutMetrics` + 1 次 evaluate）；
  扫描上限 3000 节点，超了给 `scrollables_truncated`。
- 失败不再静默：`layout` 写 `scrollables_error`，CLI/MCP 收据透出。

### 2.2 `ResolvedOp` 哨兵

- 新模块 `ashot/_ops.py`：`class ResolvedOp(dict)`。
- `dom.apply_selectors` 返回 `ResolvedOp`（不再写 `__resolved__` 键）；
  `annotate.scale_ops` 用 `isinstance(op, ResolvedOp)` 跳过二次 dpr。
- `_ALLOWED_KEYS` 移除 `__resolved__`：客户端传这个键现在是"未知字段"报错。
- 验证：JSON ops 伪造 `{"__resolved__": true}` → ValueError。

### 2.3 坐标型 op 的 `dpr` 报错

- op 级 `dpr` 只对 `selector`/`ref` 有意义；坐标型传 dpr 直接
  `ValueError("dpr 只对 selector/ref op 有效；坐标型 op 请用全局 --dpr")`，
  不再静默忽略。

### 2.4 真浏览器 E2E（可选）

`tests/test_browser_e2e.py`：

- 通过 `ASHOT_E2E=1` 开启，否则 skip；本机无 Edge/Chrome 也 skip。
- 自起浏览器：临时 profile + 随机空闲端口 + `--headless=new`，
  `Target.createTarget` 开 data: 页面，teardown `taskkill /T /F`。
- 四条锁：
  1. 原生 `<input type=range>` 拖拽 value ≥ 70（v0.6.2 的 button 修复）；
  2. snapshot 每个 ref 的 selector `querySelectorAll == 1`、密码框 text 为空；
  3. scrollables 只返回 `overflow:auto` 的容器（hidden/visible 被排除），
     且带 selector/rect；
  4. selector 标注的红框落点与按钮 rect 误差 ≤3px。

## 3. 测试

- 常规：**185 passed, 4 skipped**（E2E 默认跳过）。
- `ASHOT_E2E=1`：**4 passed in 2.84s**（本机 Edge 156 headless）。

## 4. 未做/边界

- scrollables 仍是 O(N) 扫描（上限 3000 节点）；没有换 `DOMSnapshot`。
- E2E 仅 Windows（找 Edge/Chrome 路径）；mac/Linux 需扩展路径表。
- 字段白名单是"所有 kind 的并集"，不是 per-kind schema；要做严格
  per-kind 校验需要另立 schema（且会改变错误面）。


## 5. 定位精度实测（2026-10-29，v0.6.4 CLI + 真浏览器）

在 dpr=2 的 Edge（视口 966×703，截图 1932×1406）与 3840×2160 桌面上实测；
测量方法是「原图 vs 标注图逐像素 diff 取包围盒」，避开截图里已有的红色。

| 用例 | 期望 | 实测 | 误差 |
|---|---|---|---|
| 桌面 `rect(100,100,200,100,w6)` | 97,97–303,203 | 97,97–303,203 | **0** |
| snapshot box vs element_rect（5 元素） | — | — | **最大 0** |
| `#b` selector 画框（CSS 120,80,100,40） | 240,160–440,240 | 238,158–442,242 | 中心 0；边 ±2（线宽 4 半） |
| 同框 `pad=10`（物理像素） | 228,148–452,252 | 228,148–452,252 | **0** |
| 滚 300 后 `space=document` | y +600（300×dpr2） | -440→160 | **0** |
| example.com `ref=e1` 画 `<p>` | 535,383.5–1367,485.9 | 533,382–1369,488 | 中心 0；边 ±2 |
| click+verify / range / scrollables | 1 / ≥70 / 只 `#sc` | 1 / 82 / 只 `#sc` | 通过 |

结论：**坐标误差为 0**；可见的 ±2px 是描边线宽的一半。`pad` 按物理像素
计（要 CSS 语义需自己乘 dpr）；text 的墨迹比锚点右移约 2px（字体 bearing）。
