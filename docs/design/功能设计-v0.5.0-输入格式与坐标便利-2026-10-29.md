# 功能设计 v0.5.0 —— 输入格式与坐标便利（补 imgtool 的最后差距）

> 日期：2026-10-29　版本：v0.5.0　基线：v0.4.1（commit `af38d73`）
> 缘起：与 `图片标注工具/`（Pillow 版 `imgtool.py`）逐项对比后，剩下
> 两类**便利性/输入格式**缺口：JPEG 输入、标注坐标的 CSS 换算；外加
> `info`/批量/模板三个常用便利。

## 0. 一句话

Ashot 的「能力」早已覆盖 imgtool（框/箭头/文字/裁/缩/JPEG 都有且更多），
这次补的是**用起来顺不顺**：自己产的 JPEG 能自己读、CSS 坐标能直接标、
目录能批量、常用标注能存模板。

## 1. 缺口与裁决

| 缺口 | 裁决 | 理由 |
|---|---|---|
| `annotate`/`hash`/`diff` 只吃 PNG | **补**：新增 `ashot/imageio.py`，JPEG→PNG（GDI+ 转码） | `shot --jpg`、`crop --jpg` 已在产 JPEG，自己读不了自相矛盾 |
| 标注坐标要手乘 dpr | **补**：`annotate --dpr`，只缩放坐标 | 与 `element` 返回的 CSS 矩形直接闭环；字号/线宽保持像素语义（与 imgtool `--from-css` 同口径） |
| 没有 `info` | **补**：CLI `info`，PNG/JPEG 都给 `{format,w,h,bytes,path}` | 量坐标第一步；原来得靠 hash/crop 收据绕 |
| 批量目录 | **补**：`resize --dir/--out-dir` | imgtool 文档里也标了 TODO；写文档/教程刚需 |
| 标注模板 | **补**：`annotate --template`（数组或 `{"ops": […]}`） | 常用「红框+点这里」复用 |
| `--title` 顶部标题条 | **不做** | `compose --text` 已能实现，加参数只会多一套布局语义 |
| 并排对比拼图 | **不做** | `diff` 已给差异图；并排拼图是另一种交付物，另行设计 |
| WebP/HEIC 输入 | **不做** | GDI+ 不保证支持；明确报错比「有时行有时不行」诚实 |

## 2. 实现

### 2.1 `ashot/imageio.py`（新模块）

```python
to_png(data)   # PNG 原样；JPEG 走 transform.apply(crop=全图, fmt="png")
read_png(path)
info(path)     # {format,w,h,bytes,path}
```

- 为什么绕 `transform`：GDI+ 解码/编码是现成的（`_gdi_image.ps1`），
  不引入 PIL，也不重复写 JPEG 解码器；
- 为什么 `crop=[0,0,w,h]`：`transform.apply` 有「无裁切/无缩放且 fmt=png
  就原样返回」的快路径，必须绕开它才会真正重编码。

### 2.2 顺带修掉的 bug（审查发现）

`transform.apply(jpeg, fmt="png")` 在无裁切/缩放时会走上面的快路径，
把 **JPEG 字节当 PNG 交付**（扩展名 .png、内容是 JPEG）。现在快路径
要求 `src[:8] == PNG 魔数`。这条不是本版新引入，是既有缺陷。

### 2.3 `annotate --dpr`

`annotate.scale_ops(ops, k)`：缩放 `x/y/w/h/x1..y2/x0..c2y`、`points`、
`coords`；**不缩放** `size/width/radius/block/dim`。dpr ≤ 0 报错。

### 2.4 `info` 与批处理

- `info <png|jpg>`：stdout 一行 JSON（与 `hash`/`diff` 同风格）；
- `resize --dir D --out-dir O`：只收 `.png/.jpg/.jpeg`；单张失败不中断，
  收尾 `batch: N 成功 / M 失败` 到 stderr，退出码 1 表示有失败；
- **同名冲突**：`a.png` 与 `a.jpg` 都派生 `a.png`，第二个改 `a-2.png`
  （`used` 集合 + `os.path.exists` 双保险）。

### 2.5 MCP

`ashot_annotate` 增加 `dpr`（number，缺省 0），其余工具经 `imageio`
自动获得 JPEG 输入；工具数仍 22。

## 6. v0.5.1 审查修复（2026-10-29，子 agent 只读审查）

两路审查（正确性 / 契约文档）后修复：

- **dpr 对字符串坐标/`area` 别名静默不缩放**（P1）：`scale_ops` 现在处理
  数字字符串、`area`/`coords` 逗号串；`coords` 输出小数串，`annotate._nums`
  与 `vector._nums` 改 float 解析（旧 `int("15.66")` 会崩）。
- **`info` 对非 PNG/JPEG 静默 0×0**（P1）：改为明确报错、退出码 1。
- **MCP `ashot_annotate.dpr` 被声明成 integer**（P1）：改 `0.0` → number，
  描述补 dpr 语义。
- **`annotate` 无 ops/template 静默输出原图副本**：改为报错。
- **`--template` 对象无 `ops` 键被静默当空模板**：改为报错；模板在前、
  内联在后（文档写明）。
- **`resize --dir` 重跑留陈图**：只对同批 `used` 去重，重跑覆盖旧产物；
  `--dir`/`--out` 互斥、单图 `--out-dir` 报错；非法尺寸进批前校验一次。
- **`--clip` 提示打到 stdout**：改 stderr（stdout 只留路径）。
- 文档：README 工具/命令计数、0.4.0 旧行、测试数（118/30/19）；CLI `--help`
  的「只吃 PNG」；SKILL「完全同能力」；设计索引排序。
- `dpr` 语义澄清：**0=不换算（缺省），负数报错**；text 的 `w`（布局宽）
  也会被缩放（换行位置可能变）。

测试 168 项（新增/加强：dpr bbox 实测、area/字符串缩放、info 非图报错、
模板数组/对象/坏格式、无 ops 报错、批量失败不中断、重跑覆盖、同名不同
宽高比）。
