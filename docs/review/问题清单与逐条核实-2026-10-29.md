## 2. 逐条核实

### Q01 HEAD 带 4 个红测试 —— **不复现（已修）**

- **证据**：`tests/test_ashot.py:1271-1276`、`:1383-1388` 已把桩挂到
  `cdp._ws_connect`（Session 构造期握手）与 `Session.command`（派发出口），
  不再是旧的 `cdp.call`；`:417-427` 的工具集断言已含 `ashot_cdp_view` /
  `ashot_cdp_eval`。
- **实测**：上述三条与 schema 测试全部通过。
- **残留**：确实还有 1 红，但不是这 4 条，而是 Q19（字体本地名）。
- **教训（成立，值得写进流程）**：这次事故的本质是「实现重构（dispatch 改
  Session）后测试契约没跟上」，而测试桩指向了一个已经不存在的调用点——
  **monkeypatch 的目标符号是活契约的一部分**，重构时要一起搜。

### Q02 版本号说谎 —— **不复现（已修）**

- **证据**：`ashot/__init__.py:4` = `"0.2.5"`；`ashot/mcp.py:16` 导入它，
  `:502` 的 `serverInfo.version` 同源。不存在第二处硬编码版本。
- **残留（与 Q18 同根）**：文件版本号对了，**跑着的进程**仍是 import 时的旧值；
  宿主不重拉就永远报旧版本——这不是版本号写错，是 Q18。

### Q03 dispatch 就地掏空事件 —— **不复现（已修），但修复没锁**

- **证据**：`ashot/cdp.py:822-829`
  ```python
  for raw in events:
      ev = dict(raw)          # 拷贝后再剥元信息
      if ev.pop("unresolved", False) ...
      d = float(ev.pop("_delay_ms", 0) or 0)
  ```
  注释也写明了"就地 pop 会吃掉调用方的数据"。
- **缺口**：现有测试只断言**发送出去的事件**不含 `unresolved`
  （`test_dispatch_strips_unresolved:1282`），没有断言**入参 seq 不被修改**。
  把 `dict(raw)` 改回 `raw` 这个 mutant 大概率仍然全绿——修复是真的，锁是空的。

### Q04 discover 单实例静默误伤 —— **确认（且比原报告更宽）**

- **证据**：
  - `ashot/cdp.py:132` 无条件把 `9222-9229` 塞进候选，`:135-138` 探活；
  - `ashot/mcp.py:281` / `ashot/cli.py:141` 只在 `len(ports) > 1` 时拒绝猜；
  - 单实例时直接 `ports[0]`，收据里**没有任何"目标是谁"的标识**。
  - 更宽的一处：`cli.py:96`（cdp-tabs）与 `cli.py:114`（**cdp-shot**）即便
    多实例也静默取 `[0]`——cdp-tabs 只读尚可，**cdp-shot 会把别人的浏览器
    页面拍下来**，与"输入类不许猜"的纪律不一致。
- **现实佐证**：本机 `discover()` 当前只探到 `[9222]`，即"单实例"是常态；
  一旦 awsearch 的 9223 或 ALrec 的 9225 单独活着，就会被当成目标。
- **根因**：设计里"① 枚举进程命令行 → 知道是谁拉起的浏览器"这条**在本机是死的**
  （见 Q20：WMI 拒绝访问且被静默吞），于是只剩"端口探活"这一条无身份的路。
- **建议**：单实例也要亮牌（端口 + 首个页签 title/url + 若可得的父进程名），
  让 agent 有机会发现"这不是我要的浏览器"；`cdp-shot` 与输入类同规。

### Q05 MCP 把 max_perp 当 jitter —— **不复现（已修）**

- **证据**：`ashot/mcp.py:367-376` 只传 `constrained` / `max_perp`，
  **没有** `jitter=`；`ashot/cdp.py:717` 的库缺省 `jitter=2.0`，
  `_trajectory:568` 的轴向微抖 `amp = min(jitter, max_perp)` 两边都取 2.0。
- **结论**：两调用面轨迹一致，原报告指出的笔误已不存在。

### Q06 fullpage 的 to_css —— **部分确认**

- **已修的一半**：`ashot/cdp.py:958-966` 已不再 `min(vw/w, vh/h)`，改为
  `to_css = 1/dpr`（拿不到 dpr 才退化成 `vw/w`），并留了注释说明旧坑。
- **没修的一半**：`hint`（`:968-969`）仍是"截图像素 × to_css = 点击用的
  CSS 坐标"，而 `fullpage=true` 时截图下半部分是**文档坐标**，
  `Input.dispatchMouseEvent` 要的是**视口坐标**——想点首屏以下的内容，
  必须先滚动、再减 `scrollY`。这句话没有限定语，照 hint 去点必然打偏。
- **定性**：不是数值 bug，是**收据语义 bug**（比数值错更隐蔽，因为数值是对的）。
- **建议**：`fullpage=True` 时 hint 追加"y 超出视口高需先滚动"，或收据直接给
  `viewport_only: true`；更彻底的是拍完记一个 `scrollY` 并在收据里扣掉。

### Q07 CLI annotate 缺省输出路径算错 —— **确认（已复现）**

- **证据**：`ashot/cli.py:50-51`
  ```python
  path = output.save(out, out=a.out or
                     a.image.rsplit(".", 1)[0] + "_annotated.png")
  ```
  `mcp.py:112-115` 早已改成"先看 basename 有没有点"，CLI 没同步。
- **复现**（本机实跑）：
  ```
  image = ...\.rev\my.dir\shot      （父目录带点、basename 无点）
  $ python -m ashot.cli annotate <image> '[{"kind":"text",...}]'
  C:\Users\moon\Desktop\Ashot\.rev\my_annotated.png
  backend: gdi+        ← 成功返回 0，文件写到了"上一级"
  期望：...\.rev\my.dir\shot_annotated.png
  ```
- **影响**：不报错、退出码 0、文件落在意想不到的位置（`my_annotated.png`），
  属于"静默写错地方"，比崩溃难查。
- **建议**：抽一个 `annotate.default_out(image)` 给两脸共用，顺手补测试。

### Q08 降级原因不可辨 —— **确认（已复现）**

- **证据**：`ashot/annotate_gdi.py:42-47`——`returncode != 0` 或异常，
  一律 `return None`；`annotate_png_vector:73-75` 拿到 None 就静默降级，
  收据只有 `backend="pixel"`。
- **复现**：把 `_RENDER_PS` 指向不存在的脚本（模拟"环境坏了"）后调用
  `ashot_annotate`：
  ```
  {"ok": true, "path": "...\r2_out.png", "backend": "pixel", "pixel_ops": 0}
  ```
  与"设计内降级"（老系统没有 GDI+）**完全同形**，且 `ok:true`。
- **建议**：降级时把原因带出来（`degrade_reason`: ps_rc / ps_stderr 前 200 字 /
  异常类型），并区分 `backend_fallback: true|false`。v0.1.5 挂错 DLL 那类事故
  以后才能靠收据定位。

### Q09 capture 兜底吞 GDI 原始错误 —— **确认**

- **证据**：`ashot/capture.py:213-218`
  ```python
  try:
      w, h, bgra = _shot_gdi(box)
      ...
  except Exception:                    # 裸 except，不记不报
      kind, payload = _shot_ps(box)
  ```
  主路抛什么都丢了。兜底再失败时，调用方看到的只有 PS 的错误。
- **建议**：保留 `gdi_error = "%s: %s" % (type(e).__name__, e)`，
  兜底成功时塞进收据（`"gdi_error"`），兜底失败时一并抛出。

### Q10 clip_png 用 os.system —— **确认**

- **证据**：`ashot/output.py:89-92`
  ```python
  ps = ("Add-Type ...;Set-Clipboard -Path '%s'" % tmp.replace("'", "''"))
  subprocess_ok = os.system('powershell -NoProfile -Command "%s"' % ps) == 0
  ```
- **三个具体问题**：① 双重引号拼接——路径里的 `"`、`%`、`&` 都能破坏命令；
  ② `os.system` 的 stderr 直接进控制台，MCP 场景下等于丢失；
  ③ 没有 `$ErrorActionPreference='Stop'`，PS 侧失败可能是 0 退出码。
- **建议**：与 `fonts.py` / `capture.py` 统一为 `subprocess.run([...], capture_output=True)`。

### Q11 fonts 缓存永久 —— **确认**

- **证据**：`ashot/fonts.py:26` `_CACHE = None`，`:35` 只在 None 时枚举，
  无 TTL、无 `clear_cache()` 接口。
- **影响**：常驻 MCP 进程一旦查过字库，之后装/删字体永远看不见；
  对"先 `fonts` 核名再写 `font`"这条 SKILL 用法是隐性坑。
- **建议**：加 `fonts.clear_cache()` 并暴露 CLI `fonts --refresh`；
  或给缓存加一个短 TTL（如 300s）。

### Q12 点击轨迹起点恒 (0,0) —— **确认（已实测）**

- **证据**：`ashot/cdp.py:637` `traj = _trajectory(0, 0, x, y, seed=seed)`。
- **实测**：`click_events(500, 300, seed=3)` 的首个 moved 是 `(3.38, 0.54)`，
  前三点 `(3.38,0.54) → (13.08,2.12) → (27.81,5.67)`——每条轨迹都从左上角
  出发，本身就是一条稳定的可检测指纹（真人鼠标在页面上有历史位置）。
- **建议**：让调用方传 `start=(x0,y0)`（默认随机取视口内的一个点，或复用
  上一次落点），`ashot_cdp_click` 加可选 `from_x/from_y`。

### Q13 schema 全 string + 布尔字面量重复 —— **确认**

- **证据**：`ashot/mcp.py:21-33` 的 `_tool()` 把所有参数统一
  `{"type": "string"}`——`x/y/count/timing/human` 全是字符串，
  agent 得自己猜"数字要不要加引号"。
- **字面量**：`mcp.py` 5 处、`cli.py` 7 处，共 12 处
  `in (True, "true", "True", "1")` / `not in (False, "false", "False", "0")`；
  `vector._as_bool`（`vector.py:128`）已有一份更完整的实现，却没被复用。
- **建议**：① `_tool` 支持按默认值推断类型（int/float/bool 直接出 JSON 类型）；
  ② `_as_bool` 提到 `ashot/_coerce.py`，三处共用；③ 布尔参数在 schema 里
  直接标 `boolean`，工具内仍兼容字符串（向后兼容）。

### Q14 cdp_eval 的 None/undefined + 重复 import —— **确认**

- **证据**：`ashot/mcp.py:243-246` 只对 `type == "undefined"` 加了 note；
  JS 返回 `null`、或 `returnByValue` 下不可序列化的对象，`value` 都是 `None`
  （`type` 分别是 `"null"` / `"object"`），收据同形。
- **重复 import**：`ashot/cdp.py:943` `import base64 as _b64`，而模块顶
  `:12` 已 `import base64`。
- **建议**：收据带 `value_type`（取 `result.type`），必要时把 `description`
  也带上；把 `_b64` 换成顶层 `base64`。

### Q15 text 出界：不换行 / 不裁切 / 不报错 —— **确认（三项全中）**

- **证据**：
  1. `ashot/_gdi_render.ps1:65` `$g.DrawString($s.s, $font, $brush, [float]$s.x, [float]$s.y)`
     ——**点坐标**重载，GDI+ 对画布外自动裁剪，不报错、不回传；
     全脚本只有 `dot`（编号徽章）用了 `MeasureString`（`:50`）。
  2. `ashot/vector.py:190-198` 的 text 形状只有 `x/y/s/size/color/font/bold`，
     **没有 `w`（布局矩形宽）**，也就没有换行入口。
  3. 像素降级路 `ashot/annotate.py:48-54` 的 `_px` 用
     `if 0 <= x < self.w and 0 <= y < self.h:` 直接跳过——出界像素静默丢弃。
- **实测**：200×100 画布，text 放在 `x=180` 且长于画布，收据键只有
  `['backend','ok','path','pixel_ops']`，输出仍是 200×100，无任何越界提示。
- **建议（与"高级工程师"第二轮调研一致，且这是业界最优解）**：
  - **换行**：text op 加可选 `w` → ps1 改成 `RectangleF` 布局矩形重载
    （`DrawString(String, Font, Brush, RectangleF)`），由 GDI+ 按真实字体度量
    自动折行，零估算误差；**不要**在 Python 侧按字宽猜；
  - **告警**：ps1 收尾输出各 text/dot 的 `MeasureString` 实测 bbox（JSON 到
    stdout 或旁路文件），Python 侧与画布尺寸比对，收据给
    `bounds_warn: "op[2] text 超出右边界 87px"`——**告警优于裁切**（裁切会悄悄丢内容）；
  - 像素降级路复用同一个 bbox 判断（点阵路可估算）。

### Q16 截图只回路径，多一跳 —— **确认**

- **证据**：`ashot/mcp.py:49-50`（`_shot(..., preview=False)`）、`:93`
  （`_annotate(..., preview=False)`）；**`ashot_cdp_shot` 连 `preview` 参数都没有**
  （`mcp.py:190-209`）。CLI 侧同样没有 `--preview`。
- **实测成本**：`output.preview_jpeg` 对 1920×1080 源耗时 **284 ms**、
  输出 1200×667 / 14.7 KB（纯色图；真实截图会更大）。即"缺省开 preview"
  每次多不到半秒，换来模型侧一次自检。
- **已知边界（照旧成立）**：ImageContent 在 ZCode 上**只喂模型、不渲染给用户**
  （设计 §7.10.3 定稿），所以这跳省的是"模型 read_image"，用户看图仍走 `ashot_show`。
- **建议**：`ashot_shot` / `ashot_annotate` / **`ashot_cdp_shot`** 三处缺省
  `preview=True`（保留 `"false"` 逃生口），同时把 `max_bytes` 从 500KB 压到
  约 200KB；上线前实测一次宿主对 `audience:["user"]` 的过滤行为。

### Q17 `--win` 带阴影/不可见边 —— **确认（已实测）**

- **证据**：`ashot/capture.py:173-181` 只用 `GetWindowRect`；全库无
  `DwmGetWindowAttribute` / `DWMWA_EXTENDED_FRAME_BOUNDS`。
- **实测**（本机，同一窗口，进程已 DPI-aware）：
  ```
  GetWindowRect          300 200 746 531  -> 446 x 331
  EXTENDED_FRAME_BOUNDS  311 200 735 520  -> 424 x 320
  每侧多出：L 11  T 0  R 11  B 11
  ```
  即 `--win` 截出来左右各多 11px 的不可见 resize 边、底部多 11px 阴影留白
  （数值随显示器缩放变化，方向一致）。
- **同处隐患**：`hwnd = GetForegroundWindow()` 可能为 0（锁屏/服务态/
  刚切桌面），`GetWindowRect(0)` 行为未定义，当前会返回垃圾矩形而不是可读错误。
- **建议**：`DwmGetWindowAttribute(hwnd, 9, ...)` 优先、非 0 返回回退
  `GetWindowRect`；先判 `hwnd == 0` 抛"当前没有前台窗口"。补测试锁
  （自建 tkinter 窗口，断言 DWM 尺寸 < GetWindowRect 尺寸）。

### Q18 改码后 MCP 进程是旧的 —— **确认**

- **证据**：`ashot/mcp.py:471-541` 的 `_serve` 就是 `for line in sys.stdin`
  + 分派，无 SIGHUP/文件监听/退出重建；15 个工具收据里没有任何 `ver` 字段
  （全库 grep 无 `"ver"`）；也没有 `ashot_restart` 类工具。
- **影响**：`__version__` 是对的（Q02 已修），但**进程内存里跑的是旧模块**，
  收据上看不出任何异常——这是本次复核里"最容易骗到自己"的一条。
- **建议（按性价比）**：
  1. **收据带 `ver`**（一行，`_shot/_annotate/_cdp_*` 都加）——新旧进程一秒识破；
  2. 开发期用 `mcpmon` / `mcp-hot-reload` 之类代理包一层（需 Node），
     或写进 SKILL：**开发验证走 CLI**（`python -m ashot.cli ...`，每次新进程）；
  3. 自写 `ashot_restart` 有"旧进程工具表里没有它"的鸡生蛋问题，优先级最低。

## 3. 本次复核新发现（不在原清单里）

### Q19 字体"双语命中"承诺不成立 —— 现行唯一红测试

- **现象**：`tests/test_ashot.py:821` 断言 `fonts.list_families("楷体")` 含
  `KaiTi`，实跑为 `[]`，全套测试因此 1 红。
- **实测**：本机 197 个族，`KaiTi` 的 `GetName(1033)` 与 `.Name` **都是
  `"KaiTi"`**——.NET 在这台机器上没有返回本地化名，于是 `fonts.py:52-55` 的
  双语匹配无本地名可匹配；`list_families("微软")` 同样返回 `[]`。
- **定性**：不是"测试写错了"，而是**设计承诺（§7.9.2「双语命中」）在本机不成立**。
  要么把承诺降级为"当 OS 提供本地名时"，要么从注册表
  `HKLM\...\Fonts` 补本地名映射（但那就违背了"数据源与渲染器同源"原则）。
- **建议**：把测试改成"若存在本地名则双命中"，同时把 §7.9.2 的措辞收紧；
  文档与实现必须有一边让步，不能让红测试长期挂着。

### Q20 discover 的进程枚举在本机失效，且失败被静默吞 → 每次 14 秒

- **现象**：`cdp.discover()` 实测 **14.3 s**（8 个端口 × ~1.76s 超时）。
- **根因**：`cdp.py:99-106` 跑 `Get-CimInstance Win32_Process`，本机返回
  `Access denied (HRESULT 0x80041003)`，stderr 非空但代码**只读 stdout**
  （`r.stdout.decode(...)`，从不看 `returncode`/`stderr`），于是进程枚举静默
  退化为空列表，只剩端口扫描。
- **双重后果**：
  1. 设计里"知道浏览器是谁拉起的"这条**身份信息全丢**（Q04 的直接成因）；
  2. 每个未显式 `--port` 的 cdp 调用都白付 ~14s。
- **建议**：① 检查 `returncode`/`stderr`，失败进 hint（"进程枚举被拒，已退化为
  端口扫描"）；② 端口探活并发 + 缩短 timeout（关闭端口应 <0.3s 判死）；
  ③ 枚举失败时把 `ports` 的可信度标出来（`confidence: "scan"`）。

### Q21 像素降级路只吃 8-bit RGBA

- **证据**：`ashot/annotate.py:349-352` `if depth != 8 or ctype != 6: raise ValueError`。
- **实测**：用 RGB PNG（ctype=2，最常见的导出格式）触发降级（模拟渲染脚本缺失），
  直接 `ValueError: 仅支持 8-bit RGBA PNG`——**不是降级，是失败**。
- **影响**：Ashot 自己的截图是 RGBA 所以碰不到；用户拿任意 PNG 来标注时，
  一旦矢量路不可用就暴露。
- **建议**：解码器支持 ctype 0/2/6（RGB/RGBA/灰度）与 8-bit 以外的常见情形，
  至少给"先把图转 RGBA 再标注"的可操作报错。

### Q22 CLI 的 cdp-shot 丢掉换算信息；`--ops` 被前缀匹配吞掉

- **cdp-shot**：`ashot/cli.py:116-120` 只打印 path 与 `fullpage`；
  `info` 里的 `to_css/dpr/vw/vh/hint`（MCP 面有，`mcp.py:206`）全丢——
  CLI 用户拿不到"截图像素→CSS 坐标"的依据。
- **argparse 前缀**：`annotate` 子命令的 `--ops` 不存在，但 argparse 会把它
  当作 `--ops-file` 的前缀匹配，于是 `--ops '[{...}]'` 变成"打开名为
  `[{...}]` 的文件"→ `OSError: [Errno 22] Invalid argument`（本次复核亲自踩到）。
- **建议**：`allow_abbrev=False`（全局）+ CLI 收据补 to_css。

### Q23 `os_startfile` 重复定义

`ashot/cli.py` 末尾 `os_startfile` 与 `os_startfile_impl` 两层包装，且前者
调用后者、后者才 import os——纯卫生问题，随手合并。

## 附录 A：本机跑测试的两个环境坑（不是项目缺陷）

1. **`tmp_path` 权限**：pytest 用 `mkdir(mode=0o700)` 建 basetemp，本机该 mode
   生成的 DACL 连 `listdir` 都拒绝（`icacls` 也读不了），导致 15 条测试在 setup
   阶段 `PermissionError`。绕法：`--basetemp=<工作区内新目录>` + 一个把
   `Path.mkdir` 的 mode 抹平的 `-p` 插件。
2. **`tmp/` 与 `.pytest_cache/` 的 ACL**：`tmp/` 上有
   `Everyone:(DENY)(DeleteSubdirectoriesAndFiles)`，pytest 清理 basetemp 会失败；
   `.pytest_cache/` 连 `Get-Acl` 都无权读。建议单独排查（见
   `diagnose-windows-sandbox-acl` 一类的工具），不阻塞代码审查。
