## 1. 逐条证据

### Q03 dispatch 不突变入参（补锁）
- 实现：`cdp.dispatch` 用 `ev = dict(raw)` 后再 pop。
- 锁：`test_dispatch_does_not_mutate_input_q03`——深拷贝比对 + 连续派发两次
  事件数一致。变异测试：把拷贝改回 `ev = raw` → 测试红。

### Q04 单实例也不静默 / 多实例 cdp-shot 同规
- `cdp.pick_port()`：单实例返回 `{port, source, process, warnings}`；
  多实例抛错并 `describe_ports()` 列各实例页签。`mcp._resolve_ws()` 再把
  页签 title/url 并入；`_serve` 出口把 `target` 盖进收据。
- 实测：本机曾探到 2 个实例 → `_resolve_ws(None)` 报「发现 2 个调试浏览器
  实例，不安全猜」；`ashot_cdp_view(port=9222)` 收据带 target。
- 锁：`test_pick_port_single_and_multi_q04`。

### Q06 全页坐标（文档坐标）+ S1 修正
- 判据改为**整页内容高**：`content_h > vh+1` → document，否则 viewport；
  `content_h` 缺失 → unknown；`fullpage=false` 一律 viewport。
- dpr 缺失时 `to_css_estimated: true`，hint 指引先 `cdp-view`。
- 为什么不能用图高/`dpr or 1`：`dpr` 求值失败是真实路径（evaluate 单独
  try，vw/vh 仍成功），图高已被 dpr 放大 → 视口截图会被误判成文档坐标，
  `to_css` 同时错一倍（独立审查 S1）。
- 锁：`test_cdp_shot_coord_space_q06`（含 dpr=None 三态）。

### Q07 缺省输出路径
- `annotate.default_out(image)`：先看 **basename** 有没有点；mcp/cli 共用。
- 实测：`…\my.dir\shot` → `…\my.dir\shot_annotated.png`（旧实现落
  `…\my_annotated.png`）。
- 锁：`test_annotate_default_out_q07` + `test_cli_annotate_dotted_dir_q07`。

### Q08 降级原因
- `_render_ps` 返回 `(bytes|None, reason|None, boxes)`；reason 覆盖
  `ps_rc=…+stderr` / 超时 / 无输出文件 / 异常类型。
- 实测：渲染脚本缺失 → `{backend:"pixel", backend_fallback:true,
  degrade_reason:"ps_rc=1: …"}`。
- 锁：`test_degrade_reason_surfaced_q08`。

### Q09 GDI 原始错误
- 主路异常记 `gdi_error`，兜底成功也随收据返回；兜底再失败抛两条原因。
- 锁：`test_capture_keeps_gdi_error_q09`。

### Q15 文本换行 + 越界告警
- ps1：`w>0` 走 `DrawString(RectangleF)`；text/dot 全部 `MeasureString`，
  末行 JSON `{ok, boxes:[{i,x,y,w,h}]}`。
- Python：shape 带 `i`（op 下标），path 形状精确算 bbox，text/dot 用实测值，
  `bounds_warnings()` 输出 `op[i] kind 超出画布：右 Npx`。
- 实测：200×120 画布、text 放 x=180 → `右 135px`；`w=100` 长文本实测
  bbox 宽 ≤100、高 60+（多行）。
- 像素路：点阵贪心折行；实测墨迹不越过 `x+w+20`。
- 锁：`test_text_wrap_and_bounds_warn_q15`。

### 5.1 S2（实测级）：全页坐标的**单位错**（初判"Chrome 把截图夹了"是错的）

- **初判**：抖音页 fullpage 出图 2544×1632，而当时的 `content_h=1632`
  被当成 CSS → 看起来"只截了 816 CSS 高"，于是判定 Chrome 夹了全页。
- **联网 + 实测后纠正**：`Page.getLayoutMetrics` 返回两套尺寸——
  `contentSize`（**已废弃，可能是设备像素**）与 `cssContentSize`（CSS）。
  抖音页真实内容 **1272×816 CSS**（=视口，页面没有可滚内容），
  2544×1632 正是它的 dpr=2 设备像素：**Chrome 并没有夹**。旧实现把
  `contentSize` 当 CSS 用，整页高被高估 dpr 倍。
- **对照实验**（Playwright 自带 Chromium，`browser_run_code_unsafe` 里
  开 CDP session）：941×3000 CSS 的测试页、dpr=2 →
  `contentSize=1882×6000`、`cssContentSize=941×3000`；
  `captureBeyondViewport:true` **不带 clip** 直接出 **1882×6000**（整页），
  带 clip（cssContentSize, scale=1）结果相同。**结论：不需要 clip 补丁。**
- **修法**：`layout()` 改取 `cssContentSize`/`cssLayoutViewport`（旧协议
  无 css* 时按 dpr 折算并标 `content_source`）；坐标空间优先看**图像
  覆盖的 CSS 高**（`sz[1]/dpr`）；页高超过截图上限或只截到视口时收据亮
  `fullpage_truncated` 并写明"只截到 N CSS"，不假装整页。
- **锁**：`test_layout_prefers_css_content_size_q06`（css 优先 + 设备像素
  折算两条）、`test_shot_marks_truncated_fullpage_q06`（视口截断 / 部分
  截断两态）。

### 5.2 像素降级路仍静默出界

- 上一版只给 GDI+ 路做了 bounds_warn；降级到像素画布时 text 越界仍无声
  （正是 Q15 抱怨的另一半）。
- 修法：`_estimate_boxes()` 按点阵字宽（`8*sc+2`、行高 `16*sc+4`）估算
  text/dot 的 bbox，降级路同样产出 `bounds_warn`。
- 锁：`test_pixel_fallback_bounds_warn_q15`。

### 5.3 `pick_port` 在"最小 discover 字典"上会 KeyError

- `disc["details"]` / `disc["warnings"]` 直接下标：自定义/旧版 discover
  只回 `{ports, hint}` 时抛 KeyError（等于把"发现"变成崩溃）。
- 修法：`.get(...) or []`；锁 `test_pick_port_tolerates_minimal_discover_q04`。

### 5.4 剪贴板失败信息乱码

- `clip_png` 把 PowerShell 的 stderr 按 UTF-8 解，实际是 OEM/GBK——中文
  错误提示会变乱码。修法：`_decode_console()` 依次试 utf-8/本地代码页/
  gbk/mbcs。

### 5.5 报错文案误导

- 非 8-bit 统一提示"16-bit 请先转 8-bit"，但 1/2/4-bit 调色板图也会落到
  这句。改为"16-bit/低位深请先转 8-bit"。

## 6. 联网调研记录（2026-10-29）

**问题**：`Page.captureScreenshot` 的 `captureBeyondViewport` / `clip` /
`cssContentSize` 到底怎么配合？全页截图为什么"看起来没截全"？

| 来源 | 结论 |
|---|---|
| [CDP Page 域（getLayoutMetrics / captureScreenshot）](https://chromedevtools.github.io/devtools-protocol/tot/Page/) | `clip` 的坐标是 CSS 像素、`scale` 缩放输出；`captureBeyondViewport` 默认 true；`getLayoutMetrics` 的 `contentSize`/`layoutViewport` 标注为**已废弃、可为设备像素**，应以 `cssContentSize`/`cssLayoutViewport` 为准 |
| [Chromium 协议 PDL](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/inspector/browser_protocol.pdl) | 同上（`contentSize` deprecated，`cssContentSize` 为 CSS 像素） |
| [Puppeteer ScreenshotOptions](https://pptr.dev/api/puppeteer.screenshotoptions) | fullPage 语义由 `captureBeyondViewport` + `clip` 实现，`clip` 用 CSS 尺寸 |
| [StackOverflow: clip.scale 的作用](https://stackoverflow.com/questions/76908352/) | `scale` 是输出倍率，默认 1；不能拿它当 dpr |
| 本地对照实验（Playwright Chromium，见 §5.1） | 941×3000 CSS / dpr2 → 无 clip 出 1882×6000（整页）；有 clip 同尺寸 |

**结论**：不需要给 `captureScreenshot` 加 clip；要修的是"把设备像素当
CSS 用"这个单位错误。另加 `fullpage_truncated` 作为"页太高/只截到视口"
的诚实标记。

## 7. 超长页拼接（追加，2026-10-29 深夜）

**触发**：用户追问"超长页不是有 cdp 控制鼠标滚动吗?"——此前的"截断"
不是终点，滚动拼接才是。

**实测（真机，非桩）**：
| 场景 | 结果 |
|---|---|
| Playwright 拉起的 Edge，页高 30000 CSS | 拼接 63 屏 → 746×30000，6.9s，颜色带/滚动还原全对 |
| 同浏览器，页高 60000 CSS | **单张 0.46s**（`captureBeyondViewport` 直接成功） |
| 同浏览器，20000 CSS | 单张 0.2s |
| 另一实例，17000 CSS | 单张**报错** "Unable to capture screenshot" |

→ 上限不是常数，**先试单张、失败再拼**是唯一稳的策略。

**实现**（`cdp.shot` / `cdp._stitch_fullpage` / `_scroll_to`）：
- 先单张；`RuntimeError` → 拼接；`stitch=false` 关闭兜底；
- 拼接：`document.scrollingElement.scrollTop = y`（轮询实际 scrollY），
  内层容器不动时退回 `Input.dispatchMouseEvent` 滚轮；
- 贴图按**实际** scrollY×dpr（不是目标 y——滚动会被夹在页底）；
- 画布宽=各屏最大宽，高=min(整页×dpr, 40MP/宽)，逐行切片；
- finally 复原原滚动位置；滚动不推进即停；无图/宽 0 抛错。

**验证**：97 项测试（新增拼接合成/自动触发/失败兜底 3 条）；MCP
`ashot_cdp_shot` 真机收据见 §5.7。

**诚实边界**：吸顶元素逐屏重复；拼接分辨率受 dpr 与内存限制（4K 屏
可用 CSS 高度约为上限的一半）；未测"内层滚动容器"型站点（会提前停并
标注）。

## 附录：本机跑测试的两个环境坑

1. `pytest` 的 `tmp_path` 用 `Path.mkdir(mode=0o700)` 建目录，本机该 mode
   生成的 DACL 连 `listdir` 都拒绝（`icacls` 也读不了）→ 15 条测试在
   setup 阶段 `PermissionError`。复现配方：

   ```python
   # pytest_modefix.py
   import pathlib
   _o = pathlib.Path.mkdir
   def mkdir(self, mode=0o777, parents=False, exist_ok=False):
       return _o(self, 0o777, parents=parents, exist_ok=exist_ok)
   pathlib.Path.mkdir = mkdir
   ```
   ```bash
   python -m pytest tests -q -p pytest_modefix --basetemp=.pt_run -p no:cacheprovider
   ```
2. 工作区 `tmp/` 有 `Everyone:(DENY)(DeleteSubdirectoriesAndFiles)`、
   `.pytest_cache/` 连 `Get-Acl` 都无权读——pytest 的 basetemp 清理会报警。
   建议用 `diagnose-windows-sandbox-acl` 一类的工具单独排查。
